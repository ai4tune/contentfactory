# 小掌柜 AI 升级方案：从内容工厂到线上运营助手

日期：2026-10-09

版本：需求与实施记录 v1.4

最后更新：2026-10-10

状态：U01 首批、U02 风格/成稿交付与访谈失败恢复已提交并完成合并验收，用户已于 2026-10-10 明确授权整合到 main 并发布。U02 的平台实际交付及 U03–U07 尚未完成，未安装新 Skill 或接入 DeepSeek Harness；本次发布范围和验证见第 19 节。

## 1. 本轮确定的方向

暂用产品名 **小掌柜 AI**，定位为 **帮助本地实体商家运营线上账号的 AI 助手**。“内容工厂”保留为底层内容生产能力。品牌名称尚未做商标及重名核验，正式改名另行决定。

用户打开产品，应能立即理解：这里帮助自己经营线上账号，知道目前做到了哪里、今天要干什么、接下来怎么做；也可以直接说需求，让 AI 调用产品能力完成任务。

核心价值贯穿一条流程：

```text
了解真实业务 → 建立初步方向 → 可选同行调研 → 可选运营计划
                         ↓
自己的选题 / 推荐选题 → 初稿 → 用户调整 → 审核 → 排版与素材 → 手动发布
                         ↑                                      ↓
              用户确认后的调整 ← 周复盘建议 ← 每日单篇效果检查 ← 发布记录与反馈
```

这条流程允许从“先完成一篇”进入。调研、完整知识库、风格分析和长期计划都不能成为第一次体验的统一前置条件。

### 本次用户明确确认的六项调整

| 编号 | 确认需求 | 产品含义 |
| --- | --- | --- |
| R01 | 真实经营事实与待验证定位分开 | 不确定目标客群、账号方向时可以跳过，不能把 AI 推测存成已确认事实 |
| R02 | 评估并复用已有调研 Skill | 以“老板智囊”为基础补充同行与本地运营研究，并将结论转成行动 |

| R04 | 内置写作方法与账户风格调整 | 共用方法，个人风格与样例随账户保存；临时修改和长期修改分开 |
| R05 | 增加真实照片建议 | 告诉用户建议放什么照片、为什么、放哪里、怎么拍；纳入发布交付 |
| R06 | 日检查与周复盘分开 | 日检查回答单篇是否达到预期；重大方向调整由用户主动决定或周复盘提出 |

## 2. 对外能力范围与减法

| 形式 | 当前对外目标 | 完成标准 |
| --- | --- | --- |
| 小红书图文 | 标题、正文、标签、图片次序与素材建议 | 用户审核后可以复制文字、下载图片，在平台手动发布 |
| 公众号文章 | 正文、必要配图、排版 | 提供公众号兼容的富文本复制或 HTML 交付，并验证实际粘贴结果 |
| 公众号贴图 | 图片为主要载体，搭配短文、标题和图片顺序 | 单独定义交付格式，不能把小红书文案换个名字就当作完成 |
| 抖音等视频渠道 | 视频脚本、镜头与素材建议 | 明确交付的是脚本；成片、自动剪辑和自动发布不属于本轮承诺 |

产品入口优先组织成“运营首页、内容、我的业务”。调研、计划和风格从相关任务进入，必要时保留直接入口，避免把所有能力并列成十几个主菜单。

用户不需要理解 Skill、Harness、工具调用、知识检索等实现概念。已有朋友圈、进阶创作等能力可以放到次级入口；旧内容、资料和历史记录仍必须可以找到、打开和使用。

咖啡门店可以作为首个实际验证场景，但系统让每个用户描述自己的业务，不写死咖啡、木地板等行业选择或客户默认资料。先用一类门店验证，是试点范围；通用业务输入，是产品边界。

## 3. 当前系统盘点

| 能力 | 当前实现 | 主要差距 |
| --- | --- | --- |
| 建档与定位 | 有访谈、定位预览与确认；部分未知信息会进入待补项 | 完成建档仍要求业务、定位和渠道；首篇服务仍依赖已确认 AccountContext |
| 首篇创作 | 已有首篇选题与口吻示例；存在不依赖计划的创作路径 | 快捷创作依赖已确认计划；高级创作要选资料；不同入口条件不一致 |
| 运营首页 | 已有建议任务、当前进度和 AI 输入入口 | 输入框按关键词跳转；推荐中存在固定第一周逻辑；不是持续执行的对话 |
| 运营计划 | 有生成、确认、锁定选题和后续复盘关系 | 数量仍固定为 30，周容量固定为 7/7/7/9；不是按日期和发布频率安排工作 |
| 市场雷达 | 有平台搜索、作品/账号相关查询、参考保存及历史记录 | 尚无完整全国对标研究、附近门店研究或经营机会研究流程 |
| 写作与风格 | 通用事实/写作规则、渠道规则、风格档案、样例分析和反馈均有基础 | 不是完整的任意 Skill 执行系统；需要将用户选择、试写、调整融入主流程 |
| 风格隔离 | 登录模式下风格 JSON 存储走当前个人数据空间，区分草稿和已确认风格 | 新增记忆、研究、后台任务也要沿用隔离；不能仅依赖前端账户标识 |
| 审核 | 有事实、风格、平台审核；事实修改需用户确认；有审核不可用的提示 | 还需验证完整渠道交付、图片与真实素材的体验 |
| 图片交付 | 小红书有 AI 背景封面和文字卡片生成基础 | 真实照片建议、照片使用流程和公众号贴图不是完整能力 |
| 复制与导出 | 有纯文本复制、Markdown 导出及部分图片下载 | 未形成公众号富文本复制、干净的最终正文交付和公众号贴图交付闭环 |
| 发布记录 | 有人工登记发布时间、链接、指标和主观反馈 | 不能将生成/复制视为已发布；自动取得次日数据尚未验证 |
| 周复盘 | 基于计划、周次、真实发布与反馈生成建议；样本不足会提示 | 目前依赖计划归属；需要支持无计划创作，并补每日单篇检查 |
| 长期对话与 Harness | 有工作台路线文档与可复用业务服务 | 尚未形成服务端持续对话、工具执行、账户记忆和可恢复任务的完整运行层 |

结论：已有不少业务积木，但不能说整个运营闭环已经完成。优先连接已有能力，同时补齐真正缺失的执行、研究、发布交付和反馈环节。

## 4. 首次使用：打地基，但让用户先完成一篇

### 4.1 第一屏说明用途

用一两句说明“帮你运营自己的公众号和小红书，想方向、做内容、看效果”，随后提供两个入口：

1. **先写一篇**：围绕一个主题补充最少信息，生成可修改初稿。
2. **先梳理业务与方向**：通过访谈、可选调研建立初步定位，再选择是否制定计划。

两条路径可以随时互相切换。第一次体验不要求先填完长表单、分析一圈同行或生成 30 天计划。

### 4.2 将信息拆成三种性质

| 性质 | 示例 | 保存与使用规则 |
| --- | --- | --- |
| 用户确认的真实经营事实 | 做什么业务、真实产品/服务、地址、实际可用空间、已确认价格 | 可以作为本店内容事实依据；保留来源和确认状态 |
| 用户的意愿、偏好与目标 | 想吸引新客、倾向亲切口吻、希望介绍某项业务 | 标记为用户目标或偏好，不当作已发生的经营结果 |
| AI 提议及待验证假设 | 可能适合商务会客、建议尝试某类客群、同行可能留下的机会 | 不自动升级为事实或已确认定位；支持采纳、修改、搁置 |

确认经营事实，不等于同时确认 AI 提议的完整定位。允许“我还不知道目标客群”“先不定账号方向”“先试试这个主题”。暂定定位应可正常使用，并清楚显示待验证项。

**首篇最小输入**按本次内容确定：业务大意、主题或想表达的事情、发布渠道，以及正文所需的真实细节。目标未知时可用“先介绍清楚自己的业务”作为本次内容目的，不强迫用户先确认长期增长目标。照片、价格、经历等缺失时缩小内容范围或针对性提问，不编造。

这些回答本身可成为当前内容的事实材料，不能强制用户先去知识库上传一份文件。保存到长期业务档案要有清楚的用户操作；不因为浏览页面自动完成建档。

### 4.3 首篇流程

```text
说业务与想法 → 选择渠道/内容形式 → 补当前必需信息
→ 选口吻或沿用默认 → 初稿 → 修改与审核 → 素材和排版 → 复制/下载
→ 用户实际发布后登记 → 后续补定位、调研或计划
```

可以用自己的选题，也可以使用基于本账户真实业务的入门推荐。没有同行数据时，注明推荐来自业务信息和内容方法，不说“已研究同行”。

**验收：**不确定长期定位、未确认计划、未上传文件的隔离新用户，仍能用自己提供的真实材料完成一篇；刷新后能继续；不会被快捷入口带回计划页或被首页反复送回完整访谈。

## 5. 首页：本周安排、今天行动、进展与对话

首页围绕四件事组织：

| 区域 | 用户看到什么 | 可以做什么 |
| --- | --- | --- |
| 本周安排 | 本周目标、已安排的工作、完成/待办情况 | 调整任务、查看计划；无计划时可直接创作或制定短计划 |
| 今天建议 | 当前最值得做的一件事及原因，必要时少量备选 | 继续初稿、补信息、拍照片、调研、登记反馈等 |
| 最近进展 | 已完成、进行中、等待用户、失败与下一步 | 查看结果、审核、补资料、重试或继续 |
| 对话入口 | 用户自然表达诉求，AI 展示执行进度和结果 | 直接完成工作，不要求先知道菜单位置 |

以下仅为交互示例，不能预填为任何真实门店的调研结论：

```text
本周：完成一篇店铺介绍，准备真实照片，检查发布效果
今天：初稿已完成，请确认两处产品描述；再拍一张门头照片
最近：昨天的选题已生成；同行研究还需要你确认门店位置
你可以说：看看附近几家咖啡店最近在发什么 / 把昨天那篇改得更口语
```

推荐按用户当前日期、计划周期、截止时间与状态计算，不固定读取“第一周”。用户当地日期和实际发布日用于“今天/昨天”，历史日期不能随刷新变化。

任务不只是选题：可以是访谈、调研、确认定位、收集资料、拍照、写作、审核、排版、手动发布和反馈。生成文章不等于完成“发布”任务；复制成功也不等于已发布。

**验收：**无计划、跨周、跨月、暂停任务、失败任务都有可理解的下一步；首页、聊天和内容页面的状态一致；已有历史记录仍能直接访问。

## 6. 计划：可选，按工作量安排

支持 7 天或 30 天计划，也支持不定计划直接创作。建议首次优先提供较短计划；具体默认周期和频率在界面试用中确定。

计划需要包含：周期目标、发布频率、任务类型、拟执行日期、推荐原因、依赖材料、产出和完成状态。30 天是时间范围，不代表必须写 30 篇；一周发几次由用户选择，也可以只安排一篇。

调研所得方向由用户选择后加入计划，不整批强制采纳。计划外的临时选题可独立完成，再由用户选择是否纳入计划。调整后只影响后续工作，不能覆盖已经发布内容或重写过去的计划结果。

**验收：**同样 30 天周期，低频与高频产生合理不同的发布安排；7 天计划没有后续三周的隐藏选题；无计划内容照样记录发布与反馈；研究、拍照和审核可以成为任务。

## 7. 同行调研：已有 Skill 的评估与产品改造

### 7.1 已读取的来源与结论

用户提供的[飞书文档“老板智囊：一句话做商业调研”](https://my.feishu.cn/wiki/X8yPwKRf2iaoPpkkM2XcMxDvnbh?fromScene=spaceOverview)指向 [business-advisor-v1](https://github.com/ai4tune/skills/tree/main/business-advisor-v1)。本次读取了其 `SKILL.md`、README、输入 Schema、`scripts/run.mjs` 和三个提示文件，未安装或调用模型运行。

**结论：保留并复用研究方法，另整理小掌柜的运营调研版本，不直接把原脚本当成已完成的同行研究功能。**

- 可复用：先拆研究问题、结论先行、具体建议、注明资料不足和来源边界。
- 当前边界：脚本接受 `sourceMaterials`，依次调用模型生成研究计划与报告；自身不执行搜索、附近地点查询、持续监测或账户记忆。
- 适配方向：将默认“行业趋势、AI 应用与实施建议”收窄成“同行内容、门店差异化、近期选题与下一步行动”；AI 应用咨询只在用户明确研究此问题时保留。
- 原介绍写到“确认研究计划后输出”，但当前脚本连续生成计划和报告，没有用户确认暂停点。产品应另实现必要的范围确认，不沿用宣传描述当作现有执行能力。

上述判断依据：[Skill 源码](https://github.com/ai4tune/skills/blob/main/business-advisor-v1/SKILL.md)、[运行脚本](https://github.com/ai4tune/skills/blob/main/business-advisor-v1/scripts/run.mjs)、[报告提示](https://github.com/ai4tune/skills/blob/main/business-advisor-v1/prompts/report.md)。正式接入前记录实际采用版本，来源上的后续改动不自动覆盖产品规则。

### 7.2 两类研究分开

| 类型 | 主要问题 | 所需信息与限制 |
| --- | --- | --- |
| 全国同赛道对标 | 哪些公开账号/内容值得参考，最近在讲什么，选题与表达如何组织 | 按业务、平台、时间和内容形式找样本；“公开内容表现好”不等于门店经营好 |
| 附近同行与合作机会 | 附近有哪些门店，公开可见的活动/主推/用户反馈是什么，是否存在差异化或合作假设 | 需要用户确认位置；半径可选 3/5 公里，不能把该半径当作全部业务的实际客群范围 |

“全国哪些玩得好”交付为有证据的参考样本，不冒充覆盖全国的权威排名。“附近最近如何”应标明观察窗口、公开资料时间和覆盖缺口，不能把旧资料或查不到内容的门店写成近期没有活动。

同一门店可以既有竞争关系又有合作可能，结论说明条件，不能只根据距离判定关系。主营业务、产品结构、客单和顾客选择条件缺失时保留未知。

口碑研究可加入已取得的授权评价、用户导入及允许使用的公开信息。地点搜索与完整评价访问分别验证；有地点 API 不代表有所有评价、销量或后台经营数据。

### 7.3 建议的“小掌柜同行调研”Skill 契约

这是产品专用 Skill 的设计草案，后续接入时拆成实际规则与工具；本次未创建可运行的 Skill 包。

**适用请求：**同赛道内容参考、指定同行近期情况、附近门店比较，以及基于这些资料寻找本店可验证的运营机会。用户只想写首篇时不自动触发完整研究。

**输入：**

- 用户的研究问题与这次要做的判断。
- 本账户已确认业务事实、用户目标，以及单列的待验证方向。
- 模式：全国内容对标、附近门店、指定对象或两类组合。
- 平台、时间范围；附近研究额外需要位置与半径。
- 可用的真实资料：来源标识、标题、链接或导入出处、发布时间、取得时间、原始片段/可见指标；未取得字段保持未知。
- 当前可用工具与返回情况。账户作用域由服务端注入，不让模型指定或切换所有者。

**执行规则草案：**

1. 先说明这次想解决的问题与范围；仅问影响研究的关键缺项。范围已明确的小任务直接执行；大范围或明显增加用量的研究先让用户选择范围。
2. 调用确实可用的查询工具，或分析用户提供的资料。无工具、无资料时给研究计划和待收集清单，明确“尚未完成调研”，不输出虚构同行榜单。
3. 将全国内容样本和附近门店分组，检查时间、对象、重复内容与证据来源，不把不同门店混为同一对象。
4. 区分观察事实、推测解释、适用条件与本店机会。互动数只是内容信号，不推算营业额、利润或到店转化。
5. 对高表现样本解释它讲什么、面对谁、表达结构与素材类型；若没有足够比较数据，只称为参考样本，不能声称证明了爆款成因。
6. 结合本店真实能力提出可验证方向；不可把同行的价格、活动、服务或经历挪成本店事实。
7. 输出候选选题、照片素材需求或调研下一步，让用户选择“用这个写一篇”“加入计划”“暂不采用”。策略改变需用户确认。
8. 用户触发的研究结果按账户保存并关联来源与任务；后续对话可接着使用。历史快照保留，陈旧结论须重新核实。保存与记忆归运行层管理，不在 Skill 内建另一套账户存储。

**交付：**

| 部分 | 内容 |
| --- | --- |
| 简短结论 | 回答问题，说明本次实际观察范围与可信限度 |
| 对标样本 | 对象、选择依据、近期内容/活动、可见信号、来源及时间 |
| 观察与解释 | 哪些是资料支持的事实，哪些只是可能原因 |
| 本店机会 | 可尝试方向、所需真实条件、无法满足时为什么不适合 |
| 下一步 | 可选选题、需要补的资料/真实照片、建议小实验与观察指标 |
| 缺口 | 未取得的数据、工具失败、过期来源和不能回答的问题 |

首页优先显示简短结论和下一步，完整研究供展开查看。第一次建档可以研究；用户以后也可以随时说“看看最近有什么变化”，不把研究做成一次性的入门报告。

**验收：**全国参考与本地竞争对象不混淆；每条关键判断能回到来源；无资料/接口失败不伪造结果；研究能继续到写作；账户 A 的研究不能被 B 访问；首次创作可以跳过研究。

### 7.4 工具接入顺序

先复用现有市场雷达与用户导入，验证账号/作品查询的真实覆盖和更新情况；再单独验证位置搜索与可用评价接口。需要补账号链接或昵称到平台 ID 的解析体验。周期监测、自动抓取和数据合作作为后续能力，不能因为有 Skill 文本就声称完成。

## 8. 写作方法、用户风格和审核

### 8.1 内置基础已经有什么

当前有可复用的内置写作方法：`writing-rules.ts` 管理事实和写作原则；`channel-prompts.ts` 管理平台表达；风格分析、编译和提示模块将用户确认的风格用于生成；审核模块处理事实、风格和平台问题。

所以可以回答“已经有一套写作规则基础”。但其主要形式是代码中的提示与约束，不能等同于会自动加载任意 `SKILL.md` 的完整 Skill 引擎，也不能说任意本地写作 Skill 已经接入生产。继续复用这套链路，避免再建一套平行风格档案。

### 8.2 规则组合

```text
共享的事实与写作方法 + 平台要求 + 账户已确认风格 + 本篇临时要求
```

风格只能改变表达，不能放松真实性。通用模板提供方法，不带入某个作者的姓名、履历、亲历故事或其他客户经营信息。“杏仁风格”只用于用户明确选择且适用的内容，不自动套给全部客户。

建议提供少量可理解的表达选择，例如亲切聊天、清楚专业、轻松分享；这些是待试用的选项，并非固定人格。示例尽量以同一组本账户事实展示不同表达，让用户看区别。

用户可以选默认口吻、自己描述、提供认可的文章，或对成稿说“更口语一点”。明确区分：

- **仅本篇**：不改长期档案。
- **以后默认这样写**：预览改变，并由用户明确保存/确认。
- **AI 从修改中提议新的风格**：保存为待确认建议，不能因单次反馈自动替换长期风格。

账户私有部分包括风格选择、自定义规则、样文、禁用词、修改反馈与已确认版本。共享模板可以共用，客户样文和从中提取的私有信息不能共享。重新分析后仍保留原已确认风格，直到用户确认新版本。

登录模式的风格存储已有个人空间基础；本地无登录模式不能被当作多用户隔离方案。新增缓存、后台任务和对话检索必须继续校验所有者。

### 8.3 审核与正文交付

初稿完成后允许用户修改，再核对事实、表达、平台适配及素材一致性。无依据的产品信息、第一人称经历和引文必须提示核实，不能通过“换句话说”自动变成事实；审核工具不可用时清楚说明未完成。

用户需要确认最终标题与正文。候选标题、简报、提纲、来源解释、内部审核记录与正文分开，默认复制只包含最终发布内容，避免整段候选标题或创作过程一起贴入平台。

**验收：**同样事实可预览不同口吻；临时风格不污染下一篇；长期修改经确认后跨设备继续生效；两账户相互不可见；语义审核失败不能显示“审核通过”；无事实依据时不补造故事。

## 9. 图片、真实照片和发布交付

### 9.1 真实照片建议是每篇交付的一部分

按内容主题判断是否适合真实照片，说明“建议使用你店里的实拍照片”及具体用途。不是统一推荐“门头、产品、顾客”三张，也不强制每篇必须有同样数量图片。

每条建议包含：

| 字段 | 用户得到的信息 |
| --- | --- |
| 图片目的 | 展示真实产品、让人找到店、说明空间或呈现服务步骤等 |
| 建议拍什么 | 与已知业务和本篇主题对应的具体对象；未知设施不能当作存在 |
| 怎么拍 | 取景、光线、主体、留白、横竖幅等简单可执行提示 |
| 放哪里 | 封面、第几张图、哪段正文旁，或视频的哪一镜头 |
| 缺图怎么办 | 补拍、缩减相应描述，或使用明确为示意的图形/文字卡片 |

例如，仅当用户确认店内确实有相应空间时，介绍安静会客场景的内容才建议拍该区域；不能凭运营建议虚构独立包间、插座或顾客活动。涉及顾客人物时优先使用有授权的照片或避开可识别人脸。

先完成“可执行的实拍清单”，再按需要支持上传、选择账户已有照片和与正文匹配。AI 插画、背景和文字卡片可以作为补充，但不能冒充本店、本店产品或实际顾客的实拍。

### 9.2 各渠道交付包

| 渠道 | 建议交付物 | 验收重点 |
| --- | --- | --- |
| 小红书 | 最终标题、正文、标签、封面及图片顺序、可下载素材/实拍清单 | 文字复制干净；图片可以按序取用；缺照片有明确下一步 |
| 公众号文章 | 标题、必要摘要、最终正文、图片位置、富文本复制与备用 HTML | 粘贴到后台后段落、强调与配图位置可用；图片仍需按实际后台条件补传时要明确 |
| 公众号贴图 | 图片主题与逐张内容、顺序、短文、实际适配平台的图片交付 | 真正能在目标入口发布；上线前验证当前后台形式与限制，不虚报张数/比例支持 |
| 视频脚本 | 标题/开场、逐段脚本、镜头、真实素材与口播建议 | 输出是拍摄可用脚本；无成片时不能显示“视频已完成” |

发布前至少区分：初稿、待修改/审核、用户确认、待手动发布、已登记发布。登记需要渠道与实际时间，链接可按可用情况记录；不能只依据生成完成、复制或下载事件推断已发布。

**验收：**真实照片建议与本文事实一致；最终文本不夹带候选标题和内部简报；公众号实际粘贴可用；同一内容不同渠道的发布与反馈分别记录；旧稿仍可查看及导出。

## 10. 发布反馈：每日检查单篇，周复盘讨论方向

### 10.1 在写作前明确本篇希望达到什么

可选目的包括解释产品/服务、建立认知、引导收藏、获得咨询或推广已确认活动。用户没有量化目标时，记录本篇目的和想观察的信号，不替用户编一个阅读量或到店目标。

账号长期经营目标与单篇内容目的分开。不能用所有内容的点赞数替代咨询或到店目标，也不能把某次曝光直接归因于营业增长。

### 10.2 次日单篇效果检查

每日入口查看前一天实际发布的内容；不是要求用户每天发布。已有数据就分析，暂无数据就提示补充。用户可以查看其他日期，也能重新检查尚未积累足够时间的内容。

| 检查事项 | 输出 |
| --- | --- |
| 实际发布情况 | 哪个平台、何时发布，是否只是待发布草稿 |
| 本篇目的 | 原先希望做到什么，哪些信号可以判断 |
| 真实反馈 | 可获取的指标、咨询/评论内容、用户主观反馈及来源/观察时间 |
| 判断 | 暂达到预期、暂未达到、数据不足或还需要观察；说明依据 |
| 小范围动作 | 回复咨询、澄清一处表达、补记反馈、继续观察等 |

首先支持人工输入、授权数据或导入；自动拉取需逐个平台验证接口与权限。公开同行指标不能冒充本账号后台数据。“尚未获取”不能填成零。

为内容保留发布时的目的和当时观察记录，后续反馈不能使历史判断变成用了未来数据的结论。是否新增独立指标快照存储，按真实复查需求和现有数据结构最小实现。

日检查不自动更改长期定位、目标客群、风格或账号主方向；低样本、短观察窗口明确限制，不为每天提供结论而制造因果关系。

### 10.3 周复盘与用户主动调整

周复盘综合本周内容、真实反馈、目标、执行情况和必要的同行资料，回答哪些可以继续、哪些减少、哪些值得试。无计划的实际发布也可以进入复盘；不足以判断时说明缺口。

方向变更采用：**提出建议 → 展示证据、适用条件与影响 → 用户明确选择 → 更新后续安排**。将“调整下一篇表达”与“修改长期定位”作为不同操作，不能一次确认周报就默认采纳其中全部策略。

用户主动明确要求修改方向时支持直接修改流程，展示具体改动，并记录这是用户决定。无需等下一次周复盘；意思不明确时不推定用户已同意。

新方向保留生效时间和此前版本，影响未来任务；过去内容、发布记录和原目的保留。取消或改期未来任务时，说明受影响的工作，不自动重生成全部历史内容。

**验收：**昨天无发布时没有虚构日报；无计划内容可检查和周复盘；未授权渠道数据明确未知；日检查不改定位；周报仅查看/确认阅读不等于采纳方向；明确采纳后可追溯修改依据与时间。

## 11. 对话记忆与执行层（Harness）

### 11.1 先定义产品需要，再选择框架

需要的能力是：理解用户需求、读取本账户上下文、调用现有业务服务、展示进度、保存结果与任务状态、失败后可恢复，并在下次对话接上此前工作。

目前首页输入框是关键词导航，尚未实现上述完整能力。不能通过扩大关键词表来承诺“你说什么 AI 都能做”。支持范围内直接执行；缺信息时就当前任务提问；不支持或失败时明确说明。

### 11.2 分开保存历史、记忆与正式资料

| 内容 | 作用 | 要求 |
| --- | --- | --- |
| 对话历史 | 保存聊过什么、当时调用了什么与结果引用 | 服务端持久化，随账户跨设备可继续；长对话仍可查历史 |
| 可用记忆 | 帮助下次理解上下文：事实、偏好、已确认决定、未完成事项 | 区分来源、状态与时间；修改和矛盾有处理规则 |
| 正式业务记录 | 定位、风格、计划、研究、内容、发布与复盘 | 以原业务存储为准；聊天引用记录，不维护冲突的第二份全文 |

“完整知道聊过什么”意味着原始历史可找回、相关内容能进入下一轮上下文，不意味着每次把全部聊天无上限发送给模型。初期可用近期消息、阶段摘要、明确记忆及相关记录检索；是否使用向量库在效果不足时再决定。

新的对话应能解释“我接着哪件事做”，例如恢复昨天的稿件及未确认事实。用户纠正过的信息优先；旧摘要不能重新把废弃定位当作当前目标。AI 推测不能仅因进入聊天历史就成为已确认事实。

用户能查看和纠正影响后续工作的记忆。删除某段历史或一条记忆时要说明影响，不连带删除正式内容和业务档案；具体删除行为由用户主动触发，不在升级时整理历史。

### 11.3 任务与工具

任务状态至少表达：待开始、执行中、等待用户、完成、失败；并允许用户停止未完成任务。记录具体阶段和已有结果，不只存一个“成功”标记。内容生成任务完成，不等于发布任务完成。

首批工具复用业务服务：读取本账户业务/风格、查找自己的历史内容、查询可用同行资料、创建内容、审核、形成交付、登记发布反馈、生成复盘；有明确用户动作时才更新长期方向与风格。

工具不能任意读写其他账户，不能默认获得服务器文件/命令或生产客户管理权限。查找“昨天那篇”先在当前账户记录里定位，多条候选时让用户选择，不能猜错后修改。

聊天、首页和业务页读取同一个任务与结果引用。长任务关闭页面后继续或可恢复；重试有去重，不能重复生成、重复登记发布或把失败显示成完成。用量和失败阶段可追溯，产品提示只显示对用户有用的信息。

### 11.4 隔离是服务端约束

登录身份决定个人数据空间，贯穿会话、摘要、记忆、风格、研究、任务、结果、查询缓存及文件/导出访问。对话 ID 或前端传入的 accountId 不能代替服务端授权。

后台任务绑定创建时的所有者与作用域；用户切换账户后，旧任务结果仍回到原账户。共享基础规则与公开模板可以共用，用户请求、样文、分析和派生结果仍是私有记录。

当前“一个登录用户对应个人空间”的基础先复用；“一个用户管理多门店、多社交账号及团队协作”另列后续范围，不能与本次账户隔离混为一项已完成能力。

**验收：**两账户同题研究、不同风格、相似内容不串数据；猜到其他账户记录 ID 仍拒绝访问；同账户换设备/重启可续聊；长对话能取回相关决定；纠正事实后不再用旧版本；后台切换账户、取消和重复重试均正确归属且状态可信。

### 11.5 DeepSeek Harness 的取舍

[DeepSeek Harness 官方仓库](https://github.com/deepseek-ai/deepseek-harness)可作为候选运行层。值得研究的是会话事件记录、上下文组织、工具/插件机制和执行恢复；并非替代小掌柜的业务流程、账户系统或运营规则。

官方目前将其列为实验性开发预览，明确未完成安全审计、不能按生产就绪软件对待。其记忆文档提供默认关闭的第三方 MCP 接入示例，不能理解为安装后自动获得小掌柜所需的账户长期记忆。依据：[SAFETY.md](https://github.com/deepseek-ai/deepseek-harness/blob/master/SAFETY.md)、[记忆接入说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/mcp-memory.md)。
