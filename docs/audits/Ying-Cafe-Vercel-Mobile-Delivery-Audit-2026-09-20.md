# 颖姐试点：Vercel、手机与交付核算审计

日期：2026-09-20；代码基线：`main@6475e5d`。

> 历史状态说明（2026-09-26）：本文保留了云存储改造前的审计快照。PR #44 已接入 Vercel + Supabase 客户实例能力，因此“当前不能走 Vercel”不再代表最新代码结论。当前配置与上线要求以 `docs/deployment/Vercel-Supabase-Setup.md` 和 `docs/deployment/Paid-Pilot-Deployment-Checklist.md` 为准；本文的手机与成本核算清单仍作为验收参考。

## 1. 本轮范围与结论

按用户最新要求：30 天计划、双方工作分工、资料准备与首篇共创，留到准备启动清单时再编写。本轮只确认部署可行性、检查手机缺口，最后定义交付核算。

结论：**当前内容工厂不能原样部署到 Vercel 并可靠交付；改造为外部持久化存储后可以走 Vercel。手机已有响应式基础，但尚不具备经过验收的手机使用闭环。**

目标体验：杏仁负责后台部署和资料初始化；颖姐不安装软件、不配置 API、不连接本地知识文件夹、不安装浏览器扩展，只打开网址完成日常使用。具体双方业务分工待启动阶段确定。

审计方式：源代码检查及官方文档核对。没有创建 Vercel 部署，没有修改业务代码，没有验证真实模型质量。尝试启动隔离数据的本地服务并准备浏览器检查，但 `agent-browser` 安装和开发缓存写入出现 `ENOSPC`，已停止服务。因此没有手机截图、溢出实测或真机通过证据。开发依赖仍显示 Next 16.2.10，而 package.json 已是 16.3.5；下次验收先按锁文件安装依赖。

## 2. Vercel 可行性

### 2.1 硬阻塞：持久化

当前服务端持久化不是一个可替换数据库连接地址就能迁完的结构：

| 数据 | 当前实现与代码定位 | Vercel 上需要做的工作 |
|---|---|---|
| 市场数据、调用日志 | `src/lib/db.ts`，better-sqlite3 打开本地 contentfactory.db | 迁入托管数据库；替换同步驱动和 SQLite SQL/迁移逻辑，核对数据及索引 |
| 上传文本、旧内容数据 | `src/lib/store.ts`，contentfactory.local.json | 迁到数据库，保留已有 ID 与读取兼容 |
| 建档、定位、风格、计划、草稿、审核、复盘、知识源 | 各模块 repository、`src/lib/local-store/json-file.ts`，本地 JSON | 全量盘点后迁移；条件更新/版本检查及事务处理并发，不能只迁 SQLite |
| 原始照片及生成图长期保存 | 上传接口仅接收文本；生成图片部分引用外部 URL | 接对象存储，元数据入库，验证过期、删除、访问控制、下载和跨设备读取 |
| 备份恢复 | `ops/data-maintenance.mjs` 复制本地目录 | 改为数据库备份及对象存储生命周期；完成一次隔离恢复演练 |

官方明确指出 Functions 没有共享、永久的本地文件系统，Fluid Compute 也不保证本地持久化。把数据目录改成 `/tmp`、把 SQLite 打进构建包、把 JSON 上传到部署目录，都不能解决这个问题。[Vercel SQLite 说明](https://vercel.com/kb/guide/is-sqlite-supported-in-vercel)

### 2.2 推荐目标与替代路径

若确定使用 Vercel，建议目标是：

```text
颖姐手机/电脑 → HTTPS 网址 → Vercel Next.js 页面与 API
                                      ├─ 托管关系数据库：事实、账号、计划、草稿、任务、账本
                                      ├─ 对象存储：门店照片、长期保存的输出图片
                                      └─ 模型/生图服务：密钥仅服务端配置
```

托管 PostgreSQL 可作为优先评估方向；数据库和对象存储具体供应商尚未选定。Vercel 官方提供数据库 Marketplace 集成和 Blob 存储，数据库与应用区域需要匹配。[Vercel Storage](https://vercel.com/docs/storage)

首家客户仍可独立项目、独立数据库/凭证，不要求先建公共注册、多租户或支付。单客户的轻量登录也不等于需要完整 SaaS 权限系统。

更少代码改造的路径：继续使用现有 Node/Docker，由杏仁在有持久化磁盘的服务器托管，颖姐同样只打开网址。这能减少客户工作，但需要杏仁承担服务器运维。Vercel 路线不是实现“客户免安装”的必要条件；它是部署运维选择。

### 2.3 其他上线必查项

| 项目 | 当前证据 | 所需验收 |
|---|---|---|
| 长任务 | `src/modules/plans/service.ts` 最多串行 4 批，每批 minimumTimeoutMs 为 180 秒；最坏预算可达约 720 秒加处理时间 | 对齐模型超时、函数时限、界面等待；选择合适 maxDuration，并实测。不能把默认时限当必然足够 |
| 快速创作 | 一次请求串行执行简报、生成、审核；已有部分项目持久化和重试复用 | 刷新/断网后查到任务状态，重复点击不重复创建与扣费；按实测决定是否拆为持久化后台任务 |
| 请求体 | `/api/uploads` 单文件 1 MiB，但未对整批大小设上限；目前只有 txt/md/csv | 批量文本限制总大小；手机大图使用鉴权直传对象存储，不经函数中转整个文件 |
| 图片响应 | 图片代理 route 读取外部图片；客户端 Canvas 导出 PNG | 校验图片尺寸、响应大小、地址有效期及权限，稳定保存客户需要长期复用的图片 |
| 鉴权体验 | `src/middleware.ts` 使用 HTTP Basic，当前只有实例级访问码 | 手机首次进入、再次进入、失败提示、退出/撤销访问及恢复入口实测；若 Basic 不满足，改轻量登录会话 |
| 内部运营信息 | 当前运营 API 与客户业务共用实例级访问保护 | 客户开放前为运营成本入口加独立服务端授权；仅隐藏菜单不等于限制访问 |
| 生产与预览 | 尚未检查 Vercel 项目配置 | 环境与数据库隔离，Preview 不读写客户生产数据；检查密钥、区域、域名与回滚 |
| 实际可访问性 | 尚未检查门店网络 | 用门店 Wi-Fi 和手机流量测首屏、生成、复制、取图，不预先承诺国内访问速度 |

当前官方函数文档：Fluid Compute 默认 300 秒，Pro/Enterprise 常规最大 800 秒；请求或响应体上限 4.5 MB。以实际项目配置与最新官方限制为准，不依赖扩展时限 Beta。[Functions 限制](https://vercel.com/docs/functions/limitations)

此项目面向商业客户，预算不能按 Hobby 免费方案默认成立，官方将 Hobby 限于个人非商业用途。[Hobby 说明](https://vercel.com/docs/plans/hobby)

### 2.4 Vercel 交付通过条件

- [ ] 所有权威数据迁出本地 SQLite/JSON，数据库迁移可重复执行；旧数据条数、ID、计划与草稿关联核对通过。
- [ ] 两台设备读取同一账号、资料、计划和草稿，不依赖某台电脑 IndexedDB。
- [ ] 新部署及实例重建后数据保留；并发编辑不静默覆盖。
- [ ] 文本与图片在真实配置下完成，超时、断网和重试不丢稿、不重复创建项目。
- [ ] 客户只能访问业务入口，运营核算有独立保护，密钥不进入浏览器。
- [ ] 可从备份恢复到隔离环境，明确恢复点、保留周期及客户数据删除流程。
- [ ] 在客户网络和目标手机验证完整链路后，才发送正式交付入口。

## 3. 手机端：已确认缺口与待验证项

不能把“没有横向滚动”当作手机验收完成。现在 `AppShell` 已有小屏布局和横向导航，表单有 sm/lg 断点，说明不是完全不支持手机；以下问题仍需处理。

| 优先级 | 发现 | 证据/状态 | 最小处理方向 |
|---|---|---|---|
| P0 | 本地知识库不能作为手机默认来源 | `local-index.ts` 依赖 showDirectoryPicker，不支持时明确要求桌面 Chrome/Edge；句柄和索引放 IndexedDB | 由后台上传/配置服务器可读资料，手机不要求选文件夹；换设备后资料可见 |
| P0 | 快速创作需要至少一份知识资料 | `quick-creation-workspace.tsx` 无选择就阻止生成；读取上传材料、远端来源及本机索引 | 迁移后保证预配置资料在手机可取正文，不能只显示电脑上的标题 |
| P0 | 手机照片入口缺失 | `/api/uploads` 仅 txt/md/csv，1 MiB/文件 | 增加相册/拍照上传及对象存储；规定格式、压缩、方向处理和原图权限，不让客户手动转 Markdown |
| P0 | 图片“下载”不等于“存入相册并可发布” | `xiaohongshu-visual-card.tsx` 用 Canvas、Blob、a.download；未找到 navigator.share/canShare | 增加预览/保存指引，支持时提供系统分享；真机测试图片顺序、清晰度与相册/平台可见性 |
| P0 | 未保存修改可能丢失 | `draft-detail.tsx` 编辑保存在 useState，明确点击保存；未找到离开保护或本地草稿恢复 | 自动保存或本地恢复加明确保存状态；测试切应用、误返回、刷新，不要求系统保证退出事件必定触发 |
| P1 | 复制失败后只有错误提示 | `draft-detail.tsx` 调 navigator.clipboard.writeText，catch 提示手工复制 | 可选中文本、选择/复制回退；HTTPS、权限及微信内置浏览器分别实测 |
| P1 | 长生成依赖前台等待 | 生成按钮依赖本页 generating 状态；服务端已有部分复用逻辑，但未证明跨刷新完整恢复 | 持久化任务结果与状态，重新进入可继续/查看结果；避免重复调用 |
| P1 | 页面可用性尚无实测结果 | 顶部导航横向滚动、计划编辑双列、草稿操作及大 Canvas 都需检查 | 360/390/430/768 宽度查溢出、遮挡、触控区域、软键盘和长文本；高级工具不占日常主要路径 |
| P1 | 手机登录缺少产品化验证 | Basic 浏览器原生弹窗；没有专门会话页面 | 先测 Safari/Chrome 首次、再次、错误码体验，再决定最小替换，不直接扩成多租户 |

showDirectoryPicker 属于兼容性有限的 API，不能把它当通用手机能力。[MDN](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)

### 手机验收矩阵（全部待实测）

主链路：首页 → 已有计划 → 快速创作 → 草稿编辑/确认 → 复制正文 → 取图 → 人工发布 → 返回填写记录。

- iPhone Safari、Android Chrome：主验收；微信内置浏览器：验证可用性，若不能完整支持则提供清楚的外部浏览器指引。
- 首次进入及再次进入，已有资料但本机没有目录索引。
- 生成中切后台/断网/刷新；返回后找到结果；失败重试无重复稿件。
- 编辑未点击保存时返回或切应用；恢复后内容不丢，保存状态明确。
- 复制中文、换行和标签；一次及多张图片保存后在发布平台可选择。
- 页面无非预期整页横向滚动；软键盘不挡主要按钮；长标题、空状态、错误状态均可操作。

以上是验收需求，不表示本轮已经复现所有 UI 故障。本轮静态分析明确的功能缺口与真机兼容风险应分开跟踪。

## 4. 执行依赖

1. 先确定托管路线：Vercel 需存储迁移；普通服务器复用现有持久化方案。
2. 完成云端资料和图片的跨设备访问，再处理手机取图、编辑保护与生成恢复。
3. 完成响应式及真机验收，然后跑真实部署与恢复检查。
4. 做最终交付核算；采集成本的代码需随生成和存储改造同步接入，不能等全部交付后才补采。

旧文档中“3～5 天准备”的估计不适用于新增 Vercel 迁移与完整手机改造范围。本轮不沿用旧工期承诺；在路线选定、迁移清单及真机问题收敛后重新排期。30 天业务计划与双方分工不在本节展开。

## 5. 最终交付核算

目的：确认交付完成度、每家客户的真实成本，以及后续报价所需依据。本轮只有核算口径，没有客户实际用量/价格/付款记录，不输出虚构总价或利润。

### 5.1 交付验收账

每项保存：交付项、版本/环境、验收时间、证据链接、通过/未通过/未验证、遗留问题。

必须涵盖：生产链接及访问、数据库持久化、跨设备资料、手机主链路、图片取用、任务恢复、备份恢复、成本记录。客户真实发布、第二次独立使用及反馈在启动后补记。

### 5.2 单次调用账（开发时开始采集）

- 实例标识、task_id、内容项目/计划 ID、任务类型、Prompt 版本。
- 请求模型及真实返回模型；输入/输出 Token；用量来源和覆盖情况。
- 图片张数、外部服务次数、缓存命中；成功/失败/重试及耗时。
- 单价快照、币种、估算成本；供应商结算可用时对账，不把估算当实际账单。
- Token 或单价缺失时记 null/未知，不记 0；失败请求也可能产生费用。
- 不记录完整 Prompt、知识正文和密钥；运营入口不直接开放给客户。

当前 `getOperationSummary` 在 `src/lib/db.ts` 把缺失成本汇总为 0，不能用于对外宣称“免费/零成本”。现有任务、模型、内容项目关联也未达到完整核算要求。

### 5.3 客户月账

| 成本/结果 | 核算方法 |
|---|---|
| 文本模型 | Σ 输入 Token/百万 × 输入单价 + 输出 Token/百万 × 输出单价 |
| 图片及市场服务 | 按供应商计费单位计，包括失败及重试的实际费用 |
| 托管与数据库 | 客户独享部分直接归集，共享套餐按明确分摊规则，避免把整个平台月费重复摊给每家 |
| 对象存储与流量 | 存储、上传、下载及请求费用，以账单计，免费额度单独标记 |
| 人工交付与维护 | 实际配置/陪跑/修复时间 × 内部工时成本；一次性与每月持续成本分列 |
| 产出 | 成功稿件、客户确认可发布稿件、实际发布篇数分别统计；图片张数单列 |
| 单篇成本 | 当期归属内容生产的成本 ÷ 对应成功稿件数；可发布/实际发布口径另算，分母为 0 则不可计算 |
| 收入与贡献 | 确认收入减对应周期的直接成本；缺失账单或工时则标暂估/不完整，不称已核实利润 |

月账同时显示：已知成本、未知成本调用数/比例、账单差异、失败重试占比、单客户维护时间。没有确认售价、交付周期和费用承担前，不计算 2999 元方案的确定利润。

### 5.4 完成定义

- [ ] 交付验收账有证据，未验证项单独保留。
- [ ] 至少一份真实计划、一篇真实稿件及一组配图能追溯对应调用费用。
- [ ] 7 天试用期记录可汇总；月度预测明确假设、币种和未知项。
- [ ] 对照供应商账单检查重复、失败、缺失用量及共享成本分摊。
- [ ] 输出一次性交付成本、每月持续成本与可发布单篇成本，再支持报价/续用决策。
