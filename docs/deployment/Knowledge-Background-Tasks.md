# 知识库后台任务

生成企业知识档案和目录整理建议改为先提交任务，再查询状态。提交成功后，关闭浏览器、刷新页面或换设备不会取消处理；同一客户空间的登录用户可看到进度和已保存结果。完成提醒显示在站内，浏览器关闭期间不会发送系统推送或邮件。

资料按最多 16,000 字符分批分析，每份沿用原有最多 8,000 字符的建档读取范围；每轮最多并行两批。每次 AI 调用上限 120 秒，临时故障在 10 秒后重试，最多自动重试两次。手动重试保留已完成的批次和已合并的结果。档案保存使用稳定编号，防止同一步重复执行产生重复档案。

界面显示实际阶段、已保存批次数、已等待时间和按批次数估算的参考耗时（每轮 1–3 分钟，跨批建档另计一次合并）。这是参考范围，尚未根据真实客户耗时统计校准；服务排队、模型速度和重试会延长时间。

## 部署

- Vercel：`workflow@5.0.1` 和 `withWorkflow` 自动生成运行入口。后台入口由 SDK 处理队列调用，排除应用登录 middleware；`/api/knowledge/tasks` 和重试接口仍受原有客户空间鉴权保护。生产业务状态需保持 Supabase 持久化配置。
- Docker：现有数据卷中的 `/app/data/workflow` 保存本地运行状态；不能将它放到容器临时目录。跨设备结果仍由服务端业务存储提供。
- 原同步建档/归类 API 保留兼容，但页面使用 `/api/knowledge/tasks`。旧同步 API 不具备离开浏览器后的持久任务保证。

## 验证

`npm run test:knowledge-tasks` 使用独立临时目录、本地模拟 AI 和生产构建，验证快速提交、鉴权、重复任务拦截、无页面查询时持续处理、自动重试上限、手动重试保留批次、完成后清除输入、另一客户端读取目录建议和重启后读取结果。

已失败的旧同步请求不会自动转成后台任务；升级后需重新选择资料并提交一次。
