# 小掌柜 AI 对话执行层评估

日期：2026-10-09

状态：建议方案，供用户审阅；未安装 DeepSeek Harness，未将首页导航输入框改成 AI 对话。

## 1. 建议

小掌柜需要一层 Harness 能力：维护对话上下文、选择受限工具、执行并记录任务、等待必要的用户确认、失败恢复和账户记忆。首版建议在现有系统中补一个小的执行层，复用业务服务、个人数据空间与已有 Workflow。DeepSeek Harness 保留为后续隔离验证的候选，不直接替换当前应用。

这是针对当前代码和产品范围的工程判断，不是声称已经比较过两种方案的运行效果。实际对话、长任务恢复和模型工具协议仍需实现与验证。

## 3. DeepSeek Harness 的实际边界

官方提供会话事件、工具/插件机制和执行循环，可参考其职责划分。依据：[架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)。

SDK 是从另一进程驱动完整 Harness 的方式，TypeScript 客户端启动 dsh 子进程，通过 JSON-RPC 交互；不是一个直接加到 Next.js 页面即可运行的聊天组件。需要评估宿主进程、部署生命周期和版本管理。依据：[SDK 包说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/sdk/README.md)。

会话持久化有可替换的服务契约，默认实现采用 JSONL。若接入本产品，仍需适配私有云存储、并发写入和账户所有权，不能拿共享文件目录充当租户隔离。依据：[持久化](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/persistence.md)。

其默认 Web 发布方案使用进程启动凭据及签名 Cookie，并要求反向代理处理对外访问。该身份模型不能替代小掌柜已有的登录账户和个人空间授权。依据：[Web 发布说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/public-deployments.md)。

长期记忆示例依赖另行配置的第三方 MCP 服务，默认关闭，不提供本产品账户记忆的自动隔离。依据：[记忆接入](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/mcp-memory.md)。官方标记为实验性开发预览，未完成安全审计、不能按生产就绪系统对待。依据：[SAFETY.md](https://github.com/deepseek-ai/deepseek-harness/blob/master/SAFETY.md)。

本次只读官方文档，未运行其 SDK/进程、没有性能或生产可用性结论。正式 PoC 应锁定代码版本，使用隔离的假账户和本地数据。

## 4. 两种方案的取舍

| 维度 | 在现有系统补最小执行层 | 接入 DeepSeek Harness |
| --- | --- | --- |
| 产品流程 | 直接调用现有服务；需补对话与工具协议 | 提供通用执行基础；业务工具与运营确认流程仍需适配 |
| 账户隔离 | 复用当前服务端作用域；新增存储仍须验证 | 需要将会话、工具、文件与记忆接到当前账户授权 |
| 持久化 | 复用个人空间；实现少量会话/任务记录 | 使用持久化扩展点，评估云后端和写入生命周期 |
| 后台任务 | 沿用当前 Workflow 的分步模式 | SDK 进程与现有部署、队列的关系需要验证 |
| 工具权限 | 首批只开放产品服务，便于限定范围 | 必须裁剪能力与插件，不能把通用命令/文件权限默认交给商家对话 |
| 维护 | 自己承担小范围执行逻辑、测试和恢复语义 | 承担外部版本升级、适配层及运行服务的维护 |
| 当前判断 | 更符合首版范围，建议优先实现 | 适合做隔离 PoC，达到接入条件后再决定 |

不增加 LangChain、另一套 Agent 框架、向量数据库或多 Agent，除非后续确有无法用现有结构满足的需求。减少依赖是首版选择，不是取消记忆、恢复和账户隔离要求。

## 5. U04 首版的具体交付

### 数据与上下文

- 持久化会话、消息、任务阶段、工具调用与结果引用；新存储缺失时只返回空状态，不因 GET 创建记录。
- 历史全文可查；模型上下文使用近期消息、阶段摘要、已确认资料和相关结果，不无限堆入全部聊天。
- 长期事实以企业知识档案为准，风格以已确认档案为准；记忆区分用户事实、偏好、暂定意见和 AI 建议，不自动把讨论升级成已确认定位。
- 用户纠正和明确废弃的方向优先，临时要求只影响本次；不做旧数据自动回填。

### 执行协议

首版模型输出需遵守受验证的结构化工具选择协议：回答、询问缺项或调用白名单工具。服务端校验工具名、参数和归属；不能凭模型生成的任意 URL/命令执行。

先验证当前模型网关是否支持原生工具调用；支持时采用标准消息与工具结果协议。若不支持，可先用有 Schema 校验的 JSON 动作协议，保持真实服务执行与结果记录，而非关键词跳转。该兼容选择需要真实网关验证，当前没有声称已通过。

先开放少量完整动作：读取自己的业务、查找自己的内容、按当前真实资料生成一篇、审核自己的初稿、查询现有可用的同行资料。缺位置或缺查询能力时保留任务并提问/说明，不能虚报附近调研完成。

长期定位、风格变更以及对已确认正文的覆盖需要具体用户决定；发布仍由用户手动完成。用户明确请求的可逆草稿操作不重复要求确认。工具应先校验版本，再执行；重试使用固定任务/操作标识，已完成步骤返回已有结果。

### 执行状态与页面

- 首页、对话与业务页面读取同一任务状态：待开始、执行中、等待用户、完成、失败/中断；提供停止和继续入口。
- 长任务把创建时的个人空间传给各步骤；页面关闭或用户切换账户不改变所有者。
- 对话展示真实阶段和结果链接；模型最终文本不能替代工具成功记录。生成成功与已发布分别显示。
- 会话读取、结果链接、后台回调、缓存和导出都检查服务端授权；普通商家对话不开放系统管理权限。

### 必须通过的验证

1. 同账户换设备/重启后接上历史任务；长对话中能找回相关决定。
2. 两账户相似请求不串记忆、样文、结果、缓存或文件；猜到 ID 也不可访问。
3. 网关失败、工具失败、页面关闭、重复提交和后台重试有正确状态，不重复生成/覆盖。
4. 用户纠正事实、跳过建议或仅本篇改口吻后，旧摘要不会将其恢复为当前默认。
5. 单次任务限制步骤数和调用用量；超限有可继续的说明，不无限循环。具体限制根据试用成本确定。
6. 旧版本隔离样本访问无写入，历史内容入口保留。

## 6. 何时重新考虑 DeepSeek Harness

出现较多插件接入、复杂多步恢复、跨运行环境会话等明确需求，且自有执行层维护成本明显上升时，比较已有接口与 Harness 的适配工作。

PoC 最低交付应包括：两个假账户、一个真实业务工具适配、一次中断与恢复、一次私有记忆召回、越权拒绝、重复操作去重，以及部署方式和维护成本说明。仅跑通官方聊天示例不能算小掌柜接入可行。

用户可选择优先做此 PoC；该选择不影响 U01 的首篇改动，也不授权安装框架到生产或触碰已有客户空间。
