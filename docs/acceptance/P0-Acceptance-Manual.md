# Content Factory P0 验收手册

> 对应 PRD 第 15 章场景 A / B。技术自动化不能替代实际发布、连续一周使用、客户共同审核或购买意愿访谈，这些证据必须由真实使用者填写。

## 1. 验收结论规则

只有同时满足以下条件，P0 才能标记为“可交付”：

1. `npm run test:acceptance` 全部通过；
2. 桌面 Chrome / Edge 主流程无错误覆盖层或控制台错误；
3. 至少一份真实本地资料和一份客户资料完成可追溯引用；
4. 四渠道结构确实不同，事实均能回到简报或引用；
5. AI 审核、人工编辑、保存、复制、Markdown 导出和刷新后继续编辑通过；
6. 场景 A 完成一次真实发布并连续使用 7 天；
7. 场景 B 获得客户对“能看、能改、能发”和约 3000 元方案的明确反馈。

任一项缺少真实证据时，记录为“待人工验收”，不得写成已通过。

## 2. 自动化技术验收

### 2.1 默认本地知识场景

```bash
npm run test:api
```

测试使用 `src/tests/fixtures/local-knowledge.md`，覆盖：

- 健康检查与主要错误输入；
- 账号定位分析、确认和自动复用；
- 知识源 API 不返回完整本地正文；
- 基于账号与已选知识推荐选题；
- 简报引用的 `sourceId` 与逐字原文片段；
- `ContentProject` 原子保存；
- 一次生成四个结构不同的渠道稿；
- 单渠道重试且项目 ID 不变。
- 事实、风格和平台三类独立审核；
- 应用安全建议与人工修改；
- 草稿列表、详情、版本快照和 Markdown 导出；
- 账号采集接口的来源边界、预览分析和用户确认。

### 2.2 客户资料技术演练

真实客户资料不要复制进仓库。使用绝对路径运行：

```bash
ACCEPTANCE_ACCOUNT_NAME="客户账号名" \
ACCEPTANCE_TOPIC="真实业务选题" \
ACCEPTANCE_KNOWLEDGE_FILE="/absolute/path/to/customer-material.md" \
npm run test:api
```

测试进程只读取指定文件，并在退出时恢复运行前的本地 JSON 数据。普通测试输出不打印完整正文。

## 3. 浏览器冒烟

在桌面 Chrome 或 Edge 中运行以下步骤：

1. 打开 `/`，确认默认入口是“确定选题 → 选择知识 → 生成简报 → 人工确认”；
2. 打开 `/knowledge`，选择本地目录并授予只读权限；
3. 搜索并预览一份 Markdown/TXT，确认页面展示路径与正文，服务端 `data/` 中没有目录副本；
4. 回到 `/`，选择资料并填写真实选题；
5. 生成简报，核对来源 ID、逐字片段和用途；
6. 修改简报后确认，刷新页面前记录项目 ID；
7. 全选四渠道并生成，确认每个渠道都有独立状态和结构；
8. 对单个渠道执行重试；
9. 执行 AI 审核，分别核对事实、风格和平台问题；
10. 应用安全建议，人工修改并保存，确认复制内容与编辑器一致；
11. 下载 Markdown，确认页面出现下载成功提示；
12. 打开 `/drafts` 和项目详情，保存新版本并确认上一版快照可见；
13. 检查浏览器控制台和 Next.js 错误覆盖层；
14. 截图保存最终状态，但截图不要包含敏感客户正文。

## 6. 修改量、耗时与发布性记录

每次真实交付填写一行：

| 日期 | 场景/项目 ID | 渠道 | AI 初稿字符数 | 人工增删字符数 | 修改比例 | 全流程耗时 | 可发布性 |
|---|---|---|---:|---:|---:|---:|---|
| YYYY-MM-DD |  |  |  |  |  |  | 能发 / 修改后能发 / 不能发 |

修改比例统一按以下口径计算：

```text
人工增删字符数 ÷ max(AI 初稿字符数, 1) × 100%
```

目标：修改比例低于 30%，完整生成流程低于 10 分钟。

## 7. 约 3000 元购买意愿访谈

交付演练完成后直接询问：

> 如果交付包含“第一批知识整理 + 内容工厂工具 + 首批四渠道内容 + 一次使用陪跑”，价格约 3000 元，你愿意购买吗？

只记录以下一种结论：

- 愿意：明确接受价格与交付范围；
- 有条件愿意：写清必须满足的条件、决策人和确认日期；
- 暂不愿意：写清核心异议；
- 未询问：尚未进行真实访谈。

不得把“觉得不错”“以后可以试试”记为购买意愿。
