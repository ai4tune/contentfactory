# 1. 文档目的

SBD 是 Service Blueprint Document（服务蓝图文档）。它不重复描述全部产品功能，而是明确：客户如何得到结果、系统和杏仁分别承担什么、哪里必须人工确认、一次 2999 元共创服务怎样才算交付完成。

四份文档职责：

1. PRD 决定产品范围、目标用户和成功标准；
2. SBD 决定服务流程、角色、前后台动作和交付边界；
3. Spec 决定页面、数据、接口、部署和验收契约；
4. `todo.md` 决定任务顺序和完成状态。

# 2. 服务定位

## 2.1 服务名称

对外统一名称：**AI 内容工厂·企业内容经营共创版**。

“AI Growth OS”仅作为内部架构和长期方向，不作为首批客户需要理解的产品名称。

## 2.2 服务承诺

> 用企业已有资料，和客户共同建立清晰的账号定位与 30 天内容计划，并把计划持续转成有依据、像企业自己、经过人工确认即可发布的内容。

不承诺流量、成交额或爆款；承诺过程透明、依据可追溯、内容可修改、数据归客户所有。

## 2.3 首批目标客户

- 企业负责人亲自参与，或有明确内容负责人；
- 知道线上获客重要，但不知道长期写什么、如何稳定生产；
- 已有产品、案例、FAQ、观点或历史内容，只是资料分散；
- 愿意共同确认定位、事实和内容，而不是购买无人值守代运营；
- 愿意至少真实发布一篇，并回填基本结果。

不适合首批试点：没有明确产品、拒绝提供任何事实材料、只要求保证爆款、只要全自动矩阵发布、没有人承担审核责任的客户。

# 3. 2999 元共创包

## 3.1 包含内容

- 一次企业资料盘点与最小知识包整理；
- 一份由真实资料生成、经客户确认并带来源的企业知识档案；
- 一个当前账号的定位与写作风格确认；
- 一份经营目标、内容支柱和 30 天内容计划；
- 第一周 7 个优先选题；
- 至少一次从选题到审核稿的完整共创；
- 公众号、小红书、朋友圈、短视频脚本四类能力，按客户主平台优先交付；
- 一次真实发布记录与轻量复盘；
- 一个客户独立实例、基础配置和使用说明；
- 约定周期内的问题修复与一次使用陪跑。

## 3.2 不包含内容

- 日常代运营、无限次代写和平台客服；
- 保证阅读量、粉丝增长、线索或销售额；
- 自动发布、定时发布、评论、私信或挂商品；
- 多账号矩阵、团队权限和复杂审批；
- 客户资料的长期人工整理服务；
- 新平台、新数据源或客户专属功能的无限定制；
- 广告投放、摄影、视频剪辑和真人出镜执行。

## 3.3 交付完成定义

同时满足以下条件才称为首轮交付完成：

1. 客户确认企业知识档案、关键事实来源、账号定位、风格和内容边界；
2. 客户确认 3～5 个内容支柱和一份 30 天计划；
3. 至少一篇真实内容完成生成、审核、人工修改和发布；
4. 发布链接与基础数据已记录；
5. 客户在较少陪同下完成第二次创作，或明确指出无法独立使用的阻塞；
6. 双方记录修改比例、事实问题、使用耗时和购买/续用结论。

# 4. 角色与责任

| 角色 | 必须承担 | 不应承担 |
|---|---|---|
| 客户决策人 | 确认经营目标、产品事实、账号方向、公开边界与最终发布 | 被要求理解所有技术模块 |
| 客户内容负责人 | 提供资料、选择选题、审核修改、发布、回填数据 | 从零手工整理全部定位或提示词 |
| 杏仁 / 交付顾问 | 引导建档、识别资料缺口、共创计划、解释建议、记录真实反馈 | 长期替客户运营或替客户承担事实责任 |
| AI 内容工厂 | 组织资料、生成计划、匹配依据、生成内容、执行审核、保存链路 | 对未知事实作确定性结论或保证经营结果 |
| 外部平台 / 数据服务 | 提供客户有权访问的市场或发布信息 | 成为内容创作唯一依据或单点阻塞 |

# 5. 客户旅程与服务蓝图

| 阶段 | 客户看见并完成 | 系统前台 | 杏仁与后台动作 | 核心数据 / 证据 | 失败恢复 |
|---|---|---|---|---|---|
| 0. 售前诊断 | 说明产品、目标、现状和内容困难 | 演示黄金路径和样例 | 判断是否适合共创，记录决策人和预算 | 售前访谈、付费意向、现状指标 | 不适合则停止销售，不承诺结果 |
| 1. 资料准备 | 提供最小资料或连接已有知识源 | 展示资料数量、类型、更新时间和缺口 | 协助选择代表材料，确认哪些资料可进入 AI | 来源、权限、更新时间、公开边界 | 资料不足时先做低置信档案并标注缺口 |
| 2. 企业建档 | 审阅并确认企业、产品、客户、规则和公开边界 | 从代表材料生成可编辑的企业知识档案并展示证据 | 解释字段、来源和冲突，不替客户捏造事实 | 企业知识档案版本、`AccountContext`、知识源、账号采集记录 | 可跳过非关键字段；核心事实未确认不进入发布 |
| 3. 定位与风格 | 确认账号角色、内容支柱、语气和禁用表达 | 展示 AI 分析、依据和可编辑项 | 选择代表内容，协助处理风格冲突 | 定位版本、风格版本、原文证据 | 无历史内容时建立试用风格，发布后迭代 |
| 4. 30 天计划 | 调整内容支柱、30 个选题和本周 7 题 | 解释每题目的、依据与优先级 | 用行业判断补充顺序，保留客户最终决定 | `ContentPlan`、计划项、目的、来源、状态 | 市场数据失败时用知识、痛点和历史内容生成 |
| 5. 今日创作 | 领取选题，确认 AI 选择的材料 | 自动带入账号、风格、主渠道和知识依据 | 首次陪同观察卡点，不代替日常操作 | 计划项、简报、知识引用、风格快照 | 允许增删资料、改题、重试或进入高级工作台 |
| 6. 审核发布 | 修改并确认，人工复制到平台发布 | 展示事实、AI 味/风格、品牌和平台风险 | 首篇共同审核，记录主要修改原因 | 审核结果、版本、人工修改、发布链接 | 有事实风险则阻止“可发布”确认；平台故障不丢稿 |
| 7. 数据回填 | 录入阅读、互动、线索和主观反馈 | 内容库提供简洁表单和状态 | 提醒回填，解释数据不足 | Publication、指标、客户反馈 | 无法取得指标时至少记录发布与主观结果 |
| 8. 周复盘 | 确认继续、减少或调整哪些方向 | 展示按周汇总和可解释建议 | 与客户校准建议，决定下一周 7 题 | 周期、样本数、依据、最终决定 | 数据不足只提示补充，不输出伪增长结论 |

# 6. 最小资料包

客户满足下列任一方式即可开始，不把资料整理门槛转嫁给客户：

## 6.1 连接已有知识源

- 本地 Obsidian / Markdown 文件夹；
- 飞书文档或知识库；
- 本地 GitHub 克隆目录；
- 临时上传或粘贴资料。

## 6.2 人工提供最小集合

- 一份企业或个人介绍；
- 一份核心产品/服务说明；
- 1～3 个真实案例、客户问题或 FAQ；
- 3～5 篇能够代表口吻的历史内容；
- 不能公开、不能承诺、不能使用的表达边界。

理想资料可以更多，但“10～30 份文档”不是首次进入产品的硬门槛。

# 7. 关键人工闸门

以下动作不能由 AI 静默代替：

1. 客户确认企业事实和对外公开边界；
2. 客户确认账号定位和风格；
3. 客户确认 30 天计划与本周优先级；
4. 客户可以查看并修改 AI 自动选择的知识来源；
5. 客户确认内容可发布；
6. 客户亲自完成平台发布；
7. 客户确认复盘建议是否进入下一期计划。

# 8. 数据、隐私与访问

- 每家企业使用独立实例，实例即第一阶段的数据边界；
- 本地文件夹由用户在浏览器中主动授权；企业原始资料优先留在客户自己的知识源；
- 飞书等连接只申请完成读取所需的最小权限；
- AI、图片、飞书和市场数据密钥仅保存在服务端；
- 日志保存任务类型、请求/实际模型、Token、用量来源、耗时、状态和估算成本，不保存完整 Prompt、敏感正文或生成内容；
- Token 或价格缺失时显示“未知/未配置”，不得把未知成本记为 0；
- 成本账本只用于内部经营和预算控制，首批客户不展示虚构的算力余额或积分；
- 客户可以导出和要求删除自己的账号、计划、内容和发布数据；
- 上线实例至少使用访问码或反向代理身份验证，并有备份与恢复说明；
- 涉及真实案例、客户名称、金额、个人信息和公开评价时，由客户单独确认发布授权。

# 9. 服务质量指标

## 9.1 效率

- 首次共创 30 分钟内让客户理解未来一个月的内容方向；
- 日常从选题到待审核稿不超过 10 分钟；
- 快速创作路径不超过 3 个关键操作；
- 客户能在较少陪同下完成第二次创作。

## 9.2 内容质量

- 关键事实和案例引用可追溯率 100%；
- 至少一篇真实稿件人工修改比例低于 30%；
- 内容符合确认后的账号定位和风格；
- 渠道表达不是简单缩写或扩写；
- 发现资料不足时明确提示，不补造事实。

## 9.3 商业验证

- 至少一篇真实发布；
- 至少一次发布数据或主观结果回填；
- 得到 2999 元方案的明确购买、拒绝或附条件结论；
- 记录决策人、异议、条件和确认日期；
- 不以“有人询问”代替付费验证。

## 9.4 成本与稳定性

- AI 调用用量覆盖率可见，真实 Token、估算 Token 和缺失用量必须区分；
- 能按任务、内容项目、模型和时间范围汇总文本、图片和外部数据成本；
- 能识别超时、失败率高和成本异常的步骤；
- 在交付前配置模型与图片单价，并保存调用时的单价快照；
- 成本数据只用于判断服务毛利和设置预算边界，不替代内容质量与客户结果。

# 10. 贝尔咖啡金标准

必须形成以下可复用证据包：

- 使用前：内容生产方式、频率、耗时、卡点；
- 输入：脱敏后的最小知识包清单和资料缺口；
- 决策：账号定位、主平台、风格、内容支柱；
- 计划：30 天计划和第一周 7 个选题；
- 过程：首篇生成、每轮修改、耗时、事实错误和最终稿；
- 结果：发布链接、基础指标、线索、客户主观评价；
- 独立性：客户第二次创作的操作记录和阻塞；
- 商业：2999 元报价反馈、异议和下一步；
- 宣传：可公开案例、截图和评价必须单独取得授权。

# 11. 演示脚本

演示只走一条真实黄金路径，不逐页介绍功能：

1. 打开首页，说明当前企业、本月目标和今日任务；
2. 打开内容计划，展示 3～5 个支柱、30 个选题和本周 7 题；
3. 领取一个选题进入快速创作；
4. 展示 AI 自动匹配的企业资料以及为何选择；
5. 生成内容并展示事实、风格和平台审核；
6. 人工调整并确认可发布；
7. 打开内容库，展示发布记录和下一周建议；
8. 最后再说明市场雷达、爆款和多渠道属于可选高级能力。

# 12. 交付运行清单

## 12.1 交付前

- [ ] 确认客户、决策人、内容负责人和主平台；
- [ ] 确认独立实例地址、访问方式和数据归属；
- [ ] 收到最小资料包或完成知识源连接；
- [ ] 确认哪些资料允许进入 AI、哪些可以公开；
- [ ] 生成并由客户确认企业知识档案、信息缺口和关键事实来源；
- [ ] 配置服务端密钥并设置预算边界；
- [ ] 配置当前模型、图片和外部数据单价，确认成本未知时的告警方式；
- [ ] 备份初始数据并通过健康检查。

## 12.2 共创中

- [ ] 完成企业建档、定位和风格确认；
- [ ] 完成内容支柱、30 天计划和第一周 7 题；
- [ ] 完成至少一篇内容的生成、审核和修改；
- [ ] 记录客户每个疑惑、卡点和人工修改原因；
- [ ] 检查本次内容项目的 Token、成本、耗时和错误记录是否完整；
- [ ] 不在现场临时扩展非 P0 功能。

## 12.3 共创后

- [ ] 完成真实发布和数据回填；
- [ ] 客户完成第二次创作；
- [ ] 输出一页复盘：继续、减少、调整；
- [ ] 记录 2999 元购买结论和条件；
- [ ] 备份客户数据，确认后续支持与删除方式；
- [ ] 将产品问题进入 `todo.md`，不口头承诺未排期功能。

# 13. 主要风险与处理

| 风险 | 处理原则 |
|---|---|
| 客户资料不足 | 展示缺口和置信度，先形成可修订计划，不补造事实 |
| AI 自动选材不可见 | 明示所选资料、原因和引用，允许用户增删 |
| 市场数据服务失败 | 降级为企业知识、客户痛点和历史内容，不阻塞主流程 |
| 内容仍有 AI 味 | 使用已确认风格、代表片段和专项审核，记录真实修改原因 |
| 客户把共创理解为代运营 | 售前和交付单明确责任边界与内容数量 |
| 单实例无完整权限系统 | 使用访问码、独立实例、服务端 Secret 和备份作为阶段性保护 |
| Token 或模型单价缺失 | 标记未知并展示用量覆盖率，禁止将未知成本归零 |
| 用户把 `agent.md` 当成全部知识库 | `agent.md` 只保存确认后的运行说明，原始资料继续留在客户知识源 |
| 用户期待网页后台持续读取本地目录 | 明确浏览器授权和设备边界；跨设备使用飞书/GitHub/用户同步，Local Connector 后置 |
| 演示时功能过多 | 只演示首页到发布复盘的黄金路径，高级功能后讲 |
| 有询价但没有成交 | 记录明确价格反馈、决策人和条件，不把兴趣误判为验证完成 |

# 14. 变更规则

- 新需求先判断是否直接影响首批客户完成建档、计划、创作、发布或复盘；
- 不直接影响成交和交付的需求进入 `todo.md` 后置区，不插入当前 PR；
- 新增服务承诺必须同步更新 PRD 与本 SBD；
- 新增页面、数据或接口必须同步更新 Spec；
- 完成状态与下一项任务只在 `todo.md` 更新。
