# 0. 2026-09-24 产品收敛摘要

本版继续把首批付费交付收敛为“企业内容经营共创版”，同时把自动视频作为独立的下一阶段交付路径。当前先完成 Vercel + Supabase 真实上线和使用闭环；独立视频引擎和概念样片已通过本地验收，视频线下一步是建立可跨合香、咖啡和家装场景复用的 OSS 素材底座，不是继续为单店写死素材。下文旧章节如与本节冲突，以本节和视频路线文档为准。

## 0.1 对外承诺

> 帮助企业把已有资料变成一套能持续执行的内容计划，并更快产出有依据、像自己、可以人工确认发布的内容。

第一批不卖账号数量、自动化数量或后台功能，而卖一条真正跑通的内容经营流程：建档、定位、计划、创作、审核、发布、复盘。

## 0.2 首批交付形态

- 产品：AI 内容工厂·企业内容经营共创版；
- 价格验证：2999 元/家；
- 部署：每家客户独立的 Vercel + Supabase workspace；Docker 作为本地/传统 Node 兼容方案；
- 服务：企业资料整理、企业知识档案、账号定位、内容支柱、30 天计划、第一周内容共创、使用陪跑和复盘；
- 边界：不是代运营，不承诺流量结果，不包含自动发布、矩阵运营、无限内容代写或自动视频成片；
- 首个金标准案例：贝尔咖啡。

## 0.3 用户可感知的七步

1. 企业知识库；
2. 账号定位；
3. 市场机会；
4. 内容方案；
5. 持续生产；
6. 审核发布；
7. 运营复盘。

其中市场机会为辅助输入。即使外部市场数据暂时不可用，用户仍可使用企业知识和已确认定位完成计划与创作。

## 0.4 当前优先补齐

1. 用真实 Vercel 项目、Supabase workspace 和域名验证登录、跨设备数据、移动端、备份恢复和客户删除；
2. 让贝尔咖啡或首批客户真实完成建档、计划、创作、审核、发布与复盘；
3. 保持已实现的 `ContentPlan`、任务首页、成本账本、企业知识档案和云端持久化，不再横向扩充付费试点范围；
4. 视频引擎已完成非交互契约、非黑屏/非静音验证、幂等、错误码和固定样本回归；容器环境仍待实测；
5. 视频接入按“通用素材目录 → 私有 OSS 媒体库 → 领域契约 → 异步 Worker → 成片审核/移动端 → 真实发布”顺序推进。

## 0.5 文档职责

- 本 PRD 决定“为什么做、为谁做、做什么、不做什么”；
- SBD 决定 2999 元服务如何交付以及哪些环节需要人工共创；
- Spec 决定页面、数据、接口和技术边界；
- `todo.md` 决定 PR 顺序和完成状态。

# 1. 产品结论

第一版不建设完整 SaaS 平台，而是验证一项可以被企业购买和持续使用的能力：

> 用户连接企业资料或个人知识库，完成企业建档和账号定位，得到可编辑的 30 天内容计划，并持续把计划选题生成适配不同渠道、可审核、可发布的内容。

第一版不是后台管理系统、数据采集平台或自动发布平台。产品价值取决于企业是否知道接下来发什么、生成结果能否少改就发、流程能否持续执行，以及客户是否愿意为共创交付付费。

# 2. 第一版商业验证目标

## 2.1 核心假设

企业或个人创作者愿意为以下能力付费：

1. AI 能理解其真实业务资料和个人表达风格；
2. 同一个选题可以快速适配多个内容渠道；
3. 生成结果经过少量修改即可发布；
4. 内容生产从偶发行为变为可以持续执行的流程。

## 2.2 第一版成功标准

使用以下结果判断第一版是否成功：

1. 输入一组真实资料，30 分钟内能够形成可解释的 30 天内容方向；
2. 一个已确认选题可生成公众号文章、小红书笔记、朋友圈文案、短视频脚本，日常默认只生成主渠道；
3. 从领取选题到得到待审核稿不超过 10 分钟；
4. 至少一篇真实内容的人工修改比例低于 30%，关键事实可追溯率为 100%；
5. 客户完成至少一次真实发布，并能在较少陪同下独立完成第二次创作；
6. 贝尔咖啡或首批意向企业对 2999 元共创方案给出明确购买、拒绝或附条件购买结论。

## 2.3 辅助观察指标

- 一次完整生成流程是否能在 10 分钟内完成；
- 用户是否能连续一周使用，而不是只体验一次；
- 用户每周发布频率是否提高；
- 每篇内容人工修改比例是否低于 30%；
- AI 是否能准确引用知识库中的产品、案例和观点；
- 四种渠道内容是否真正适配渠道，而不是简单改写长度。

辅助指标用于判断问题，不替代上述核心成功标准。

# 3. 目标用户与使用场景

## 3.1 首批用户

### 杏仁本人

- 已有本地 Obsidian 知识库；
- 知识库已通过 GitHub 同步；
- 需要生成公众号、朋友圈、小红书和短视频内容；
- 用于高频内部验证产品是否真正节省时间。

### 贝尔咖啡 / 首批付费意向企业

- 企业资料可能分散在飞书文档、本地文件和已有业务材料中；
- 不一定能自己整理出清晰账号定位和内容方向；
- 需要先知道未来 30 天发什么，再看到真实资料如何转化为能发布的内容；
- 需要在较少陪同下完成第二次创作；
- 贝尔咖啡作为首个金标准样本，其他询价用户作为后续付费验证候选。

## 3.2 日常任务

用户每天真正需要完成的任务只有：

1. 今天写什么；
2. 应该使用哪些真实资料；
3. 需要生成哪个渠道的内容；
4. 生成结果有没有事实、风格和平台风险；
5. 修改后如何快速复制发布。

当计划项未来选择“最终短视频”时，日常任务还需包含素材确认、成片审核、替换问题片段和下载发布；这是后续范围，不计入当前 P0 交付。

# 4. 产品原则

1. 轻量内容经营总览是首页，内容创作是最主要的日常入口并保持一键可达；
2. 账号定位只在首次使用或方向变化时执行；
3. 知识库归用户所有，产品不建设自有企业云盘；
4. 爆款拆解不是生成内容的必经步骤；
5. 自动发布不是第一版价值验证对象；
6. 用户可以只生成一种渠道，也可以一键生成全部四种渠道；
7. 四种渠道共享事实和核心观点，但使用不同的渠道表达；
8. 所有内容必须经过 AI 审核和人工确认；
9. 第一版优先解决“内容能不能发”，不优先解决管理、统计和自动化；
10. 只有当用户持续使用并愿意付费后，才增加平台化能力。
11. Skill 是通用方法，企业知识是客户事实，账号/品牌画像是客户个性，本次任务是临时输入；四层不得混写成客户专属代码；
12. Token 与成本只作为内部经营和风险控制依据，第一版不建设客户积分、充值或套餐额度系统；
13. 每家客户的独立实例就是首批交付的数据边界，不为未来多租户提前增加当前没有用途的组织、成员和角色代码。

# 5. 产品主流程

## 5.1 首次使用流程

```text
进入企业建档向导
→ 连接本地文件夹、飞书或导入最小企业资料包
→ AI 从代表性材料生成企业知识档案并标注证据与缺口
→ 用户编辑并确认企业、产品、客户、规则和公开边界
→ 采集已有账号或根据资料建立初始定位
→ 确认目标客户、经营目标、主平台、账号定位和写作风格
→ AI 生成内容支柱、30 个候选选题和本周 7 个选题
→ 用户人工调整并确认内容计划
→ 进入今日任务首页
```

最小资料包不要求用户在现场一次准备 10～30 份文档。企业介绍、产品/服务、1～3 个真实案例或 FAQ、3～5 篇代表内容，或者连接一个已有知识文件夹即可开始。资料不足时系统必须展示缺口，不得假装定位完整。

没有历史账号的新用户可以跳过插件，通过企业资料建立初始定位。插件、市场数据和爆款采集都不能阻塞首次计划生成。

企业知识档案不是全部知识正文的副本，也不是第二套云盘。它是从现有知识源编译出的、可编辑且带版本的企业经营上下文；原始资料仍归用户自己的本地文件夹、飞书或其他知识源所有。

## 5.2 日常创作流程

```text
进入首页查看今日任务
→ 从本周计划领取一个选题
→ 自动继承账号、风格、主渠道和内容目的
→ AI 匹配知识资料并向用户展示选择依据
→ 用户增删资料或直接确认
→ AI 生成统一内容简报与主渠道内容
→ AI 执行事实、风格、平台审核
→ 用户人工修改
→ 用户确认内容可发布
→ 人工复制发布
→ 手工记录链接、数据与主观反馈
→ 系统形成下一周继续、减少或调整建议
```

需要多渠道、指定资料、爆款改写或精细控制时，用户进入高级创作工作台。快速模式不删除已有高级能力。

每个计划项需要有明确交付类型。当前旧数据默认按现有主渠道生成文字稿；后续才允许选择最终短视频并进入 `VideoProduction`。

## 5.3 后续增强流程

```text
内容审核完成
→ 推送到各平台草稿箱
→ 用户人工确认发布
```

自动采集爆款、推送平台草稿箱和自动发布均不属于第一版主流程。手工录入爆款、AI 拆解和爆款改写是 V1 可选创作模式，不是原创模式的前置步骤。

# 6. 账号定位

## 6.1 产品角色

账号定位是整个内容生产流程的长期上下文，不是独立的分析报告，也不是每次创作的前置表单。

一个实例第一版只保存一个当前账号。用户主动“更新账号定位”时覆盖当前定位，不提供多账号切换。

## 6.2 浏览器插件采集方式

插件定位为“账号采集助手”，读取用户当前浏览器登录状态下有权限看到的信息。

第一版支持引导式采集：

1. 用户打开账号主页；
2. 点击“采集账号信息”；
3. 插件读取当前页面可见的账号名称、简介、粉丝量、内容列表和互动数据；
4. 用户可继续打开代表性内容或创作者后台，补充采集正文和后台指标；
5. 采集结果发送到内容工厂进行 AI 分析。

第一版不承诺：

- 绕过登录、验证码或平台权限；
- 获取页面没有展示的隐藏数据；
- 自动遍历账号全部历史内容；
- 稳定替代平台官方数据后台；
- 大规模监控或爬取第三方账号。

## 6.3 定位分析输出

- 账号名称和平台；
- 账号定位；
- 目标客户；
- 核心产品或服务；
- 内容转化目标；
- 内容支柱；
- 表达风格和品牌语气；
- 常用表达；
- 禁用或不适合的表达；
- 历史高表现主题与结构；
- 当前账号问题；
- 下一阶段内容方向；
- 推荐首批选题；
- 分析依据与信息缺口。

定位确认后，用户可以单独建立一份默认写作风格档案。系统从风格指南、禁用词、5～10 篇经过确认的历史内容和人工改稿记录中提取可编辑规则，每条关键规则保留原文依据。风格档案不与事实知识或爆款结构混为一个提示词。

## 6.4 验收标准

- 插件可以采集当前页面可见信息；
- 用户不需要手工整理大量历史内容；
- 定位分析结果可由用户确认和编辑；
- 定位保存后，选题与内容生成自动使用；
- 用户可以跳过或更新定位；
- 账号定位不会要求用户每次重复填写。

# 7. 知识库

## 7.1 产品角色

知识库为内容提供企业事实、产品、案例、观点和表达素材。产品不复制用户整个知识库，不建设自有云盘。

## 7.2 知识源类型

统一支持以下知识来源模型：

```text
本地文件夹
飞书文档或知识库
GitHub 仓库
临时上传文件
```

第一版实施优先级：

1. 本地文件夹中的 Markdown、TXT；
2. 已验证可访问的飞书文档或多维表格；
3. 本地 GitHub 克隆目录；
4. GitHub 远程仓库连接；
5. Word、PDF 和其他格式解析。

GitHub 远程连接属于 P1。本地已克隆的 GitHub 仓库在第一版按普通本地文件夹读取。

## 7.3 本地文件夹读取

- 第一版限定桌面 Chrome / Edge；
- 用户通过浏览器主动选择知识库文件夹；
- 产品只获得用户明确授权目录的读取权限；
- 浏览器本地枚举文件和读取正文；
- 用户修改文件后可以刷新知识列表；
- 换设备后需要重新选择本地或同步下来的文件夹；
- 产品不负责同步本地文件夹。

## 7.4 知识同步责任

用户可以使用 GitHub、Obsidian Sync、iCloud、OneDrive 或其他同步工具在设备间同步文件夹。

内容工厂只负责读取当前设备可访问的文件，不建设新的同步系统。

## 7.5 知识选择策略

第一版不建设复杂向量数据库和 RAG：

1. 读取文件名、标题、标签和正文；
2. 根据选题执行标题、关键词和正文搜索；
3. 推荐 5～10 份候选资料；
4. 用户确认本次使用哪些资料；
5. 只把确认后的必要正文或片段发送给 AI；
6. 生成结果展示引用来源。

## 7.6 企业知识档案

首次建档在已有知识源之上生成一份经过人工确认的企业知识档案，至少包含：

- 企业与品牌简介；
- 核心产品、服务与报价边界；
- 目标客户、典型问题与期望行动；
- 真实案例、事实和可公开证据；
- 品牌语气、常用表达和禁止表达；
- 当前内容目标与主要渠道；
- 信息缺口、冲突和待确认项；
- 每个关键事实的来源引用。

档案必须支持草稿、人工确认、版本和更新时间。系统可以把确认后的档案导出为 `agent.md`、`brand.md`、`audience.md`、`products.md` 和 `content_rules.md`，但 `agent.md` 只保存精炼后的运行说明，不承载全部原始资料。

账号定位、企业/客户/产品字段和风格画像仍使用现有权威数据对象。用户确认知识档案时，重叠字段先回写对应权威对象，再生成带来源的档案版本，避免出现两套互相冲突的企业资料。

## 7.7 隐私边界

- 不默认上传整个本地知识库；
- 不在普通日志保存完整知识正文；
- 只在用户发起生成时读取本次必要资料；
- 清晰展示将发送给 AI 的来源；
- AI Key 不暴露在前端；
- 本地目录权限可以由用户撤销；
- 飞书和 GitHub 只申请最小只读权限。
- 本地文件夹默认只读；只有用户主动导出企业档案时才单独申请写入权限；
- 企业知识档案保存事实摘要、规则和来源标识，不默认复制完整原文。

# 8. 选题

## 8.1 输入方式

用户可以：

- 手工输入明确选题；
- 从账号定位推荐方向中选择；
- 让 AI 基于账号定位和知识库推荐；
- 从已保存爆款的拆解结果中选择改写方向。

## 8.2 第一版选题输入

必填：

- 选题标题或核心问题。

可选：

- 内容目标；
- 目标客户补充；
- 希望使用的产品或案例；
- 行动引导；
- 补充要求。

账号定位、目标客户和品牌语气默认自动继承，不要求重复填写。

# 9. 内容生成

## 9.1 第一版渠道

固定支持四种：

1. 公众号文章；
2. 小红书笔记；
3. 朋友圈文案；
4. 短视频脚本。

用户可以多选，也可以一键生成全部。

## 9.2 统一内容简报

生成渠道内容之前，AI 先形成统一内容简报：

- 目标受众；
- 内容目标；
- 核心观点；
- 事实、产品和案例证据；
- 内容结构；
- 行动引导；
- 使用的知识来源；
- 必须人工确认的信息。
- 可选的爆款来源、钩子、结构和改写角度。

用户可以确认或直接进入生成。所有渠道共享这份事实基础。

原创模式至少选择一份知识资料。爆款改写模式可以不选知识，但爆款只作为结构和表达参考，不得成为事实、案例或数据证据；一旦选择自己的知识资料，以自己的资料为事实优先来源。

## 9.3 渠道适配要求

### 公众号文章

- 完整论述；
- 结构清晰；
- 结合案例和证据；
- 适合长文阅读；
- 提供标题和摘要。

### 小红书笔记

- 提供多个标题；
- 前三行有明确钩子；
- 短段落和高信息密度；
- 有收藏价值；
- 避免明显 AI 腔和过度营销。

### 朋友圈文案

- 更口语和个人化；
- 适合熟人信任关系；
- 不写成长文章；
- 弱化营销感；
- 提供自然互动或咨询入口。

### 短视频脚本

- 前三秒钩子；
- 口播正文；
- 节奏或停顿建议；
- 必要画面提示；
- 结尾行动引导；
- 当前版本不生成或剪辑视频，`short_video_script` 仍是可单独审核和导出的渠道稿。

### 最终短视频（下一阶段）

- 不扩展 `ChannelDraft` 承载素材、渲染和成片状态，而是创建独立 `VideoProduction`；
- 以已确认脚本和分镜为输入，经过素材匹配、配音、配乐、渲染、技术检查和人工成片审核；
- 素材必须记录来源、权利、用途和客户归属；
- 成片不得因“渲染成功”自动标记为可发布，必须通过非黑屏、非静音、时长/尺寸、字幕可读性和人工确认。

## 9.4 生成要求

- 四种内容不是简单缩写和扩写；
- 事实必须来自用户确认的知识资料；
- 无资料支持的内容应标记为推断或待确认；
- 账号定位和品牌语气必须作为生成上下文；
- 标题、大纲、统一简报和渠道稿件必须使用同一份已确认风格契约；
- 内容项目保存当次风格版本快照，后续更新默认风格不改变旧稿；
- 单次创作可以增加临时风格要求，但不得覆盖账号默认风格；
- 爆款作者的口吻默认不进入个人风格档案；
- 每种输出可单独重新生成；
- 用户修改后的版本可保存；
- 生成内容可以复制或下载 Markdown。

# 10. 审核与人工修改

## 10.1 审核维度

### 事实审核

- 是否引用了知识库中不存在的信息；
- 产品参数、价格、案例是否准确；
- 是否把 AI 推断写成事实；
- 是否有必须由用户补充的信息。

### 风格审核

- 是否符合当前账号定位；
- 是否符合既有表达风格；
- 是否存在明显 AI 腔；
- 是否过度营销；
- 是否使用禁用表达。

审核必须以内容项目保存的风格版本快照为准，避免默认风格更新后改变旧稿判断标准。第一版先提供确定性禁用表达检查和基于规则、样例的 AI 审核；用户改稿差异只有在明确确认后才进入后续风格更新。

### 平台审核

- 内容形式是否适配渠道；
- 是否存在夸大、敏感或违规表达；
- 篇幅、标题、结构是否合理；
- 是否存在直接搬运或侵权风险。

## 10.2 交互方式

审核与编辑在内容结果页完成，不建设独立复杂审批中心。

用户可以：

- 查看问题和修改建议；
- 一键接受可自动修复项；
- 手工编辑正文；
- 保存修改版本；
- 复制最终内容；
- 下载 Markdown。

- 图片生成和外部数据服务的调用次数、单价快照和估算成本。
- 后续视频领域的结构化脚本、分镜、素材元数据、渲染任务、输出文件索引、审核与调用成本。

第一版不需要保存：

- 用户整个本地知识库副本；
- 完整第三方平台历史数据；
- 多组织和成员关系；
- 支付订单；
- 复杂发布指标；
- 完整行为审计系统。
- 面向客户的积分、算力余额和计费订单。

托管客户实例的业务状态保存到 Supabase Postgres，当前图文生成资产保存到 Supabase Storage；后续视频、音乐、代理文件、中间产物和成片保存到独立私有 OSS。素材元数据、授权、可剪片段和引用关系保存到 Postgres，不把媒体二进制写入 JSONB。本地/Docker 兼容模式保留 JSON、SQLite 和持久化目录。

缺少 Token 或价格配置时必须显示“未知/未配置”，不得把未知成本展示为 0。调用元数据不得保存完整 Prompt、完整知识正文、密钥或完整生成内容。

# 14. 风险与处理方式

## 14.1 插件采集稳定性

风险：第三方平台页面结构变化、登录状态、验证码和可见数据范围不同。

处理：采用用户主动打开页面后的引导式采集，保留人工补充和跳过定位入口，不承诺后台爬虫。

## 14.2 本地文件夹浏览器兼容性

风险：本地目录读取能力不能覆盖所有浏览器。

处理：第一版明确限定桌面 Chrome / Edge，并保留文件上传和飞书作为兜底。

## 14.3 知识资料过多

风险：一次发送大量资料导致成本高、生成质量下降。

处理：先搜索候选资料，再由用户确认，限制每次实际发送的文档和正文长度。

## 14.4 四渠道内容同质化

风险：四种输出只是长度不同，无法体现渠道适配价值。

处理：统一内容简报与渠道 Prompt 分离，对每种渠道设置独立验收规则。

## 14.5 内容事实错误

风险：AI 编造产品、案例、价格或观点。

处理：强制引用来源、区分事实与推断、执行事实审核、保留人工确认。

## 14.6 功能再次膨胀

风险：继续增加爆款、发布、看板、付费和自动化，导致主流程迟迟不可用。

处理：P1 和 P2 不进入开发，除非 P0 已通过真实连续使用和付费验证。

## 14.7 成本不可见

风险：网关没有返回 Token、`smart` 路由的实际模型未知或模型单价未配置，导致成本被错误显示为 0，无法判断客户毛利。

处理：分别记录请求模型、实际模型和 Token 来源；单价随调用保存快照；缺失数据标为未知；内部看板展示用量覆盖率和未知成本调用数。

## 14.8 视频生产稳定性与素材权利

风险：本地 PoC 可以生成样片，但全自动入口仍可能产生黑屏、静音或错配素材；未记录授权来源的素材不能进入商业交付。

处理：先在独立引擎完成固定样本回归和技术验证；产品侧建立权利字段、私有签名访问、成片人工闸门和可删除链路，未达标前不宣布可付费交付。

## 14.8 本地知识与跨设备预期不一致

风险：用户误以为线上网站可以在未授权时持续访问任意本地目录，或认为换设备后会自动拥有同一份本地知识。

处理：明确浏览器只访问用户主动授权的目录，换设备需要重新授权；跨设备优先使用飞书、GitHub 或用户自己的同步工具；后台常驻 Local Connector 后置。
