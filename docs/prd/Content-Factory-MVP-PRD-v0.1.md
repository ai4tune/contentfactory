# 1. 产品结论

第一版不建设完整 SaaS 平台，只验证一项核心能力：

> 用户连接企业资料或个人知识库，确定一个选题，选择需要的内容渠道，由 AI 生成可审核、可修改、可复制发布的内容。

第一版不是后台管理系统，也不是自动发布平台。产品价值取决于生成内容能否提高真实内容生产频率，并让首个试点客户愿意付费。

# 2. 第一版商业验证目标

## 2.1 核心假设

企业或个人创作者愿意为以下能力付费：

1. AI 能理解其真实业务资料和个人表达风格；
2. 同一个选题可以快速适配多个内容渠道；
3. 生成结果经过少量修改即可发布；
4. 内容生产从偶发行为变为可以持续执行的流程。

## 2.2 第一版成功标准

只使用以下三个标准判断第一版是否成功：

1. 输入一组真实资料，可以生成公众号文章、小红书笔记、朋友圈文案、短视频脚本四种渠道内容；
2. 生成内容经过少量修改即可发布，不需要整体重写；
3. 崔总体验真实流程后，愿意支付约 3000 元购买“知识整理 + 内容生产能力 + 首批内容交付”。

## 2.3 辅助观察指标

- 一次完整生成流程是否能在 10 分钟内完成；
- 用户是否能连续一周使用，而不是只体验一次；
- 用户每周发布频率是否提高；
- 每篇内容人工修改比例是否低于 30%；
- AI 是否能准确引用知识库中的产品、案例和观点；
- 四种渠道内容是否真正适配渠道，而不是简单改写长度。

辅助指标用于判断问题，不替代三个核心成功标准。

# 3. 目标用户与使用场景

## 3.1 首批用户

### 杏仁本人

- 已有本地 Obsidian 知识库；
- 知识库已通过 GitHub 同步；
- 需要生成公众号、朋友圈、小红书和短视频内容；
- 用于高频内部验证产品是否真正节省时间。

### 崔总

- 企业资料可能分散在飞书文档、本地文件和已有业务材料中；
- 不一定能自己整理出清晰账号定位和内容方向；
- 需要看到真实资料如何转化为能发布的内容；
- 是约 3000 元首笔付费意愿的验证对象。

## 3.2 日常任务

用户每天真正需要完成的任务只有：

1. 今天写什么；
2. 应该使用哪些真实资料；
3. 需要生成哪个渠道的内容；
4. 生成结果有没有事实、风格和平台风险；
5. 修改后如何快速复制发布。

# 4. 产品原则

1. 轻量内容经营总览是首页，内容创作是最主要的日常入口并保持一键可达；
2. 账号定位只在首次使用或方向变化时执行；
3. 知识库归用户所有，产品不建设自有企业云盘；
4. 爆款拆解不是生成内容的必经步骤；
5. 自动发布不是第一版价值验证对象；
6. 用户可以只生成一种渠道，也可以一键生成全部四种渠道；
7. 四种渠道共享事实和核心观点，但使用不同的渠道表达；
8. 所有内容必须经过 AI 审核和人工确认；
9. 第一版优先解决“内容能不能发”，不优先解决管理、统计和自动化；
10. 只有当用户持续使用并愿意付费后，才增加平台化能力。

# 5. 产品主流程

## 5.1 首次使用流程

```text
安装或启用浏览器插件
→ 打开已有账号主页或创作者后台
→ 插件采集当前可见的账号与内容信息
→ AI 生成账号定位与风格分析
→ 用户确认并保存为当前唯一账号
→ 连接本地文件夹、飞书或其他知识源
→ 进入内容创作页
```

没有历史账号的新用户可以跳过插件，通过少量企业资料建立初始定位。插件不能阻塞内容创作。

## 5.2 日常创作流程

```text
输入或选择选题
→ 系统推荐相关知识资料
→ 用户确认本次使用的资料
→ 勾选内容渠道
→ AI 生成统一内容简报
→ AI 生成各渠道内容
→ AI 执行事实、风格、平台审核
→ 用户人工修改
→ 复制、下载或保存草稿
```

## 5.3 后续增强流程

```text
爆款采集与拆解
→ 作为选题和结构参考

内容审核完成
→ 推送到各平台草稿箱
→ 用户人工确认发布
```

以上两条均不属于第一版主流程。

# 6. 账号定位

## 6.1 产品角色

账号定位是整个内容生产流程的长期上下文，不是独立的分析报告，也不是每次创作的前置表单。

一个实例第一版只保存一个当前账号。用户主动“更新账号定位”时覆盖当前定位，不提供多账号切换。

## 6.2 浏览器插件采集方式

插件定位为“账号采集助手”，读取用户当前浏览器登录状态下有权限看到的信息。

第一版支持引导式采集：

1. 用户打开账号主页；
2. 点击“采集账号信息”；
3. 插件读取当前页面可见的账号名称、简介、粉丝量、内容列表和互动数据；
4. 用户可继续打开代表性内容或创作者后台，补充采集正文和后台指标；
5. 采集结果发送到内容工厂进行 AI 分析。

第一版不承诺：

- 绕过登录、验证码或平台权限；
- 获取页面没有展示的隐藏数据；
- 自动遍历账号全部历史内容；
- 稳定替代平台官方数据后台；
- 大规模监控或爬取第三方账号。

## 6.3 定位分析输出

- 账号名称和平台；
- 账号定位；
- 目标客户；
- 核心产品或服务；
- 内容转化目标；
- 内容支柱；
- 表达风格和品牌语气；
- 常用表达；
- 禁用或不适合的表达；
- 历史高表现主题与结构；
- 当前账号问题；
- 下一阶段内容方向；
- 推荐首批选题；
- 分析依据与信息缺口。

## 6.4 验收标准

- 插件可以采集当前页面可见信息；
- 用户不需要手工整理大量历史内容；
- 定位分析结果可由用户确认和编辑；
- 定位保存后，选题与内容生成自动使用；
- 用户可以跳过或更新定位；
- 账号定位不会要求用户每次重复填写。

# 7. 知识库

## 7.1 产品角色

知识库为内容提供企业事实、产品、案例、观点和表达素材。产品不复制用户整个知识库，不建设自有云盘。

## 7.2 知识源类型

统一支持以下知识来源模型：

```text
本地文件夹
飞书文档或知识库
GitHub 仓库
临时上传文件
```

第一版实施优先级：

1. 本地文件夹中的 Markdown、TXT；
2. 已验证可访问的飞书文档或多维表格；
3. 本地 GitHub 克隆目录；
4. GitHub 远程仓库连接；
5. Word、PDF 和其他格式解析。

GitHub 远程连接属于 P1。本地已克隆的 GitHub 仓库在第一版按普通本地文件夹读取。

## 7.3 本地文件夹读取

- 第一版限定桌面 Chrome / Edge；
- 用户通过浏览器主动选择知识库文件夹；
- 产品只获得用户明确授权目录的读取权限；
- 浏览器本地枚举文件和读取正文；
- 用户修改文件后可以刷新知识列表；
- 换设备后需要重新选择本地或同步下来的文件夹；
- 产品不负责同步本地文件夹。

## 7.4 知识同步责任

用户可以使用 GitHub、Obsidian Sync、iCloud、OneDrive 或其他同步工具在设备间同步文件夹。

内容工厂只负责读取当前设备可访问的文件，不建设新的同步系统。

## 7.5 知识选择策略

第一版不建设复杂向量数据库和 RAG：

1. 读取文件名、标题、标签和正文；
2. 根据选题执行标题、关键词和正文搜索；
3. 推荐 5～10 份候选资料；
4. 用户确认本次使用哪些资料；
5. 只把确认后的必要正文或片段发送给 AI；
6. 生成结果展示引用来源。

## 7.6 隐私边界

- 不默认上传整个本地知识库；
- 不在普通日志保存完整知识正文；
- 只在用户发起生成时读取本次必要资料；
- 清晰展示将发送给 AI 的来源；
- AI Key 不暴露在前端；
- 本地目录权限可以由用户撤销；
- 飞书和 GitHub 只申请最小只读权限。

# 8. 选题

## 8.1 输入方式

用户可以：

- 手工输入明确选题；
- 从账号定位推荐方向中选择；
- 让 AI 基于账号定位和知识库推荐；
- 后续从爆款拆解结果中选择。

## 8.2 第一版选题输入

必填：

- 选题标题或核心问题。

可选：

- 内容目标；
- 目标客户补充；
- 希望使用的产品或案例；
- 行动引导；
- 补充要求。

账号定位、目标客户和品牌语气默认自动继承，不要求重复填写。

# 9. 内容生成

## 9.1 第一版渠道

固定支持四种：

1. 公众号文章；
2. 小红书笔记；
3. 朋友圈文案；
4. 短视频脚本。

用户可以多选，也可以一键生成全部。

## 9.2 统一内容简报

生成渠道内容之前，AI 先形成统一内容简报：

- 目标受众；
- 内容目标；
- 核心观点；
- 事实、产品和案例证据；
- 内容结构；
- 行动引导；
- 使用的知识来源；
- 必须人工确认的信息。

用户可以确认或直接进入生成。所有渠道共享这份事实基础。

## 9.3 渠道适配要求

### 公众号文章

- 完整论述；
- 结构清晰；
- 结合案例和证据；
- 适合长文阅读；
- 提供标题和摘要。

### 小红书笔记

- 提供多个标题；
- 前三行有明确钩子；
- 短段落和高信息密度；
- 有收藏价值；
- 避免明显 AI 腔和过度营销。

### 朋友圈文案

- 更口语和个人化；
- 适合熟人信任关系；
- 不写成长文章；
- 弱化营销感；
- 提供自然互动或咨询入口。

### 短视频脚本

- 前三秒钩子；
- 口播正文；
- 节奏或停顿建议；
- 必要画面提示；
- 结尾行动引导；
- 第一版不生成或剪辑视频。

## 9.4 生成要求

- 四种内容不是简单缩写和扩写；
- 事实必须来自用户确认的知识资料；
- 无资料支持的内容应标记为推断或待确认；
- 账号定位和品牌语气必须作为生成上下文；
- 每种输出可单独重新生成；
- 用户修改后的版本可保存；
- 生成内容可以复制或下载 Markdown。

# 10. 审核与人工修改

## 10.1 审核维度

### 事实审核

- 是否引用了知识库中不存在的信息；
- 产品参数、价格、案例是否准确；
- 是否把 AI 推断写成事实；
- 是否有必须由用户补充的信息。

### 风格审核

- 是否符合当前账号定位；
- 是否符合既有表达风格；
- 是否存在明显 AI 腔；
- 是否过度营销；
- 是否使用禁用表达。

### 平台审核

- 内容形式是否适配渠道；
- 是否存在夸大、敏感或违规表达；
- 篇幅、标题、结构是否合理；
- 是否存在直接搬运或侵权风险。

## 10.2 交互方式

审核与编辑在内容结果页完成，不建设独立复杂审批中心。

用户可以：

- 查看问题和修改建议；
- 一键接受可自动修复项；
- 手工编辑正文；
- 保存修改版本；
- 复制最终内容；
- 下载 Markdown。

# 11. 页面与信息架构

第一版只保留五个主要入口：

```text
首页
内容创作
当前账号
知识库
草稿历史
```

## 11.0 首页

- 展示当前账号、定位和内容方向；
- 统计本地与在线知识素材、内容项目、已审核、已发布、阅读和点赞；
- 展示最近内容；
- 提供内容创作、当前账号、知识库、草稿历史和发布数据快捷入口；
- 只展示真实已记录数据，没有数据时显示 0 和明确空状态。

## 11.1 内容创作页

建议布局：

```text
左侧：知识库搜索与资料选择
中间：选题、目标和渠道选择
右侧：统一内容简报与四种渠道结果
底部：引用来源、审核结果和人工编辑
```

必须支持：

- 看到当前账号定位摘要；
- 输入或选择选题；
- 搜索并选择知识资料；
- 多选内容渠道；
- 生成、审核、修改、复制；
- 保存草稿。

## 11.2 当前账号页

- 插件采集入口；
- 当前账号和采集来源；
- 账号定位与内容风格；
- 下一阶段内容方向；
- 推荐选题；
- 编辑和更新定位。

## 11.3 知识库页

- 选择本地文件夹；
- 连接飞书；
- 展示已连接知识来源；
- 展示文件或文档列表；
- 搜索、刷新、预览；
- 显示隐私和发送边界。

## 11.4 草稿历史页

- 选题；
- 创建时间；
- 已生成渠道；
- 审核状态；
- 最后修改时间；
- 进入继续编辑；
- 复制和下载。

第一版只建设轻量内容经营首页，不建设图表分析、复杂后台、发布管理中心和运营周报页。

# 13. 数据保存边界

第一版只需要保存：

- 当前账号定位；
- 知识源连接和文档元数据；
- 用户主动选择的必要引用片段；
- 选题与统一内容简报；
- 各渠道草稿及修改版本；
- 审核结果；
- 模型、Prompt 版本、调用时间和状态。

第一版不需要保存：

- 用户整个本地知识库副本；
- 完整第三方平台历史数据；
- 多组织和成员关系；
- 支付订单；
- 复杂发布指标；
- 完整行为审计系统。

在首个付费验证前，本地 JSON、浏览器 IndexedDB 或单实例轻量持久化均可；不因未来 SaaS 提前建设复杂数据库。

# 14. 风险与处理方式

## 14.1 插件采集稳定性

风险：第三方平台页面结构变化、登录状态、验证码和可见数据范围不同。

处理：采用用户主动打开页面后的引导式采集，保留人工补充和跳过定位入口，不承诺后台爬虫。

## 14.2 本地文件夹浏览器兼容性

风险：本地目录读取能力不能覆盖所有浏览器。

处理：第一版明确限定桌面 Chrome / Edge，并保留文件上传和飞书作为兜底。

## 14.3 知识资料过多

风险：一次发送大量资料导致成本高、生成质量下降。

处理：先搜索候选资料，再由用户确认，限制每次实际发送的文档和正文长度。

## 14.4 四渠道内容同质化

风险：四种输出只是长度不同，无法体现渠道适配价值。

处理：统一内容简报与渠道 Prompt 分离，对每种渠道设置独立验收规则。

## 14.5 内容事实错误

风险：AI 编造产品、案例、价格或观点。

处理：强制引用来源、区分事实与推断、执行事实审核、保留人工确认。

## 14.6 功能再次膨胀

风险：继续增加爆款、发布、看板、付费和自动化，导致主流程迟迟不可用。

处理：P1 和 P2 不进入开发，除非 P0 已通过真实连续使用和付费验证。

# 15. MVP 验收场景
